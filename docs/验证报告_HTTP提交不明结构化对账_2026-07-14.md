## 1. 优先级复核

启动时交接所列唯一 P0 为 HTTP `submission_unknown` 结构化对账写入口。当前源码复核确认该判断仍成立：

- 提交回执前断连虽然不会自动重 POST，但 Job、reserved Publication 和同节点新版本会永久锁住；
- Browser 已有 `found/not_found` 思路，HTTP 没有独立修订、核心命令或 MCP 写入口；
- 任意 free-text Publication `failed/cancelled` 又会被 Generation 当作权威终态，存在绕过重复付费保护的跨存储旁路。

本轮没有重复建设已验证的 HTTP `waiting_remote`、隔离下载、关键帧或主轨渲染模块，而是完成上述缺口的纵向切片。

## 2. 实现结果

### 2.1 独立检查点与严格证据

- `GenerationJob` 增加 `HttpGenerationSubmissionCheckpoint`，以独立 `revision` 管理 `submission_unknown → reconciled_found/reconciled_not_found`。
- `found` 必须提供稳定 `externalTaskId`、`evidenceReference`、方法和说明。
- `not_found` 必须额外提供 `confirmNoRemoteResult=true`，不能携带远端身份、结果 URL、最终目标或 partial 文件。
- 方法限定为 `provider_task_list / client_job_id_search / provider_idempotency_lookup / provider_request_log / provider_support`。
- note 与 evidenceReference 在进入命令账本前拒绝 URL、Bearer、API key、Cookie、密码、token、signature 等敏感内容。

### 2.2 核心、命令与 MCP

- 新增核心 `reconcileHttpGenerationSubmission`，在现有 generation 跨进程锁内完成 CAS。
- `found` 保留原 `clientJobId/attempt`，绑定原远端任务并转 `waiting_remote`；命令本身不发 POST、GET、轮询或下载。
- `not_found` 先以结构化来源关闭旧 Publication，再将旧 Job 写为 failed；只有两者闭合后，现有入队保护才允许显式新版本。
- 新增 CommandRequest `reconcile_http_generation_submission` 和第 134 个 MCP 命名工具；外层统一要求 `requestId + idempotencyKey`。
- 对账结果被窄化，账本、回放、Generation Resource 与直接工具都不返回完整 Job、prompt、令牌或签名 URL。
- stale revision、非法 ID 和缺证据属于已确认无副作用失败，命令账本写 `failed`，不留下虚假的 `unknown`。

### 2.3 Publication 终态来源与竞态

- Generation-owned Publication 终态增加结构化 provenance，并绑定 project/job/item、clientJobId、attempt、externalTaskId、checkpoint revision 和 cause。
- Publication `registered` 始终优先；对账旧窗口不能覆盖并发成功回执。
- 自由文本、旧版或修订不匹配的 `failed/cancelled` 不再终结 Job，也不释放同节点重复提交锁；Doctor 要求 `inspect_publication`。
- 覆盖 Publication 已关闭但 Job 尚未写盘的崩溃窗，可从 provenance 恢复 `reconciled_not_found`。
- 远端取消返回与 Publication 注册并发时，注册成功胜出，不制造本地 cancelled。

### 2.4 同域回归修复

- Browser `downloaded` 后只处理焦点 `jobId`，不会顺带提交其他 queued 任务。
- Browser `not_found` 与远端 confirmed failure/cancelled 使用同一结构化 Publication 来源合同。
- 历史 registered Publication 的复验现在只在 Job 真正从非终态恢复时推进节点；不会把已通过导演验收的“已完成”节点降回“待视频验收”。
- HTTP/Browser 续接包、Doctor、统一快照、Capabilities 与恢复 Prompt 均区分各自检查点和可执行动作。
