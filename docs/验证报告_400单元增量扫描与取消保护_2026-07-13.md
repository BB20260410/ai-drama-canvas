## 结论

本轮将真实文件扫描从“每次对所有媒体重复 Sharp/ffprobe”改为有边界的增量机械验收，并把取消语义接入桌面手动扫描与文件监听：

- 每次仍重新发现真实候选路径，不把 SQLite 当作完成事实；
- 仅在文件尺寸、mtime、ctime、检查器版本或哈希需求变化时重新机械检查；
- 图片、视频和音频分别保留 Sharp/ffprobe 真实解码门禁；
- SHA-256 改为 1 MiB 分块流式读取，不再把最多 100 MB 文件整体读入内存；
- 媒体机械检查并发固定为 6；
- 同项目扫描由跨进程 `scan` 锁串行化；
- 提交点前取消不会覆盖上一份 JSON 索引、SQLite 缓存或追加 `project.scanned`；
- 提交开始后会完整写完索引、缓存和事件，避免因晚到取消产生半份状态；
- 桌面扫描按钮在运行时变为“取消扫描”，文件监听遇到更新会取消旧轮次并合并为新扫描；
- `scan_project`、`get_progress`、Doctor 和统一快照均可读取新检/复用统计。

## 文件抖动与退出恢复

`npm run ui:scan-shutdown-smoke` 在真实 Electron 中完成以下序列：

1. 打开已有完整索引的一单元隔离项目并启动文件监听；
2. 320 ms 内连续重写同一 60 KB 视频 4 次；
3. 监听器把抖动合并为 1 轮扫描，只启动 1 个假 ffprobe；
4. ffprobe 仍在运行时由应用截图流程触发正常退出；
5. `before-quit` 取消探测并等待活动扫描释放后再退出。

同一门禁随后直接使用签名安装包中的 `AI 漫剧画布.app/Contents/MacOS/AI 漫剧画布` 重跑；结果仍为退出码 0、1 轮 ffprobe、子进程终止、scanId 不变、1 条扫描事件和 0 把锁。证据：[安装包窗口截图](./evidence/scan-shutdown-recovery-packaged.png)、[安装包恢复指标](./evidence/scan-shutdown-recovery-packaged.metrics.json)。

## 未越界与剩余边界

- 只创建和读取 `/tmp` 隔离项目；没有扫描或修改 `/Users/hxx/Desktop/Ai漫剧`、`豆包版本`、`黄金面具`、`封神篇`。
- 增量机制仍会遍历候选路径并执行 `stat`，这是为了确保文件系统继续作为事实来源；它优化的是昂贵解码与哈希，不是假设目录没有变化。
- Sharp 元数据读取本身不能在 native 调用中途强制终止，但调用完成后立即响应取消；ffprobe 和流式哈希可由 AbortSignal 中断。
- MCP 写扫描继续经过幂等命令账本和项目锁；本轮没有把客户端取消强行映射为“扫描成功”，避免污染命令终态语义。
- 用户尚未提供真实生图/图生视频网站，真实登录、付费提交和生成质量仍未校准；视觉判断仍需人工验收。
- 安装包尚未 Apple 公证。
