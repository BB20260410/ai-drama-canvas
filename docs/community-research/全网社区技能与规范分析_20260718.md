## 0. 项目真相（分析前提）

本仓库不是“提示词合集”，而是：

- 本地、隔离、可扩展的 **AI 短剧素材知识中心**
- **无限画布** 上可视季/集/15s 单元/2–6 宫格/资产/异常队列
- **Codex/MCP** 在生图前冻结 BindingSet + 连续性 + SHA/硬锁
- 软件保证：**身份、版本、引用、SHA、门禁、证据闭包**；像素级同脸由 Review 裁决

已完成：P0–P7（P5 资产库、P6 BindingSet、P7 九字段连续性与六图停检）  
下一步：P8 只读生产驾驶舱（尚未落代码）  
正式生图：**仅 Codex imagegen**；禁止 Artlist/网页/Chrome 供应链

因此社区资源必须分成两类：

| 类型 | 用途 |
|------|------|
| **A. 软件工程向** | 画布性能、资产/审片模型、MCP 边界 → 服务 P8–P10 |
| **B. 内容生产向** | 剧本/分镜/角色锁/提示词 → 服务未来 imagegen pack 与用户文案 |

混用会出事：例如把 Higgsfield Playwright 自动化 skill 接进正式链，直接违反项目红线。

## 2. 分域深度分析

### 2.1 内容生产：剧本 → 资产 → 分镜 → 片段

#### 社区共识流水线（Big Prompt Hub + Reddit 2026）

```text
Premise / Story Engine
→ Episode Beat Map
→ Character Casting Bible（locked vs changeable）
→ Reference Still Pack
→ Continuity-safe Shot Cards
→ Clip-by-clip render
→ Drift QA + Episode Acceptance
```

这与本项目目标链路**同构**：

```text
剧本 → 实体提及 → 候选检索 → 人工消歧
→ AssetBindingSet → 连续性 → 冻结 pack
→ imagegen → raw/labeled + Review → 下一格引用
```

| 社区步骤 | 本项目已有/缺口 |
|----------|-----------------|
| Casting bible | P5 CanonicalAsset + 硬锁 ✅ |
| Reference pack | CAS + AssetVersion + SHA ✅ |
| 消歧 | P6 BindingSet，禁止静默选 ✅ |
| Continuity | P7 九字段 + 上格 raw ✅ |
| Drift QA | Review + checkpoint ✅ |
| 全局可视驾驶舱 | **P8 缺口** |
| 规模与恢复 | **P9 缺口** |

**可吸收的字段规范**

- locked fields / scene-changeable 分离 → 对齐 Authority 与 per-panel override
- drift log 必须随成片保留 → 对齐追加式 Review，禁止“修好删证据”
- 一 clip 一 job → 对齐 generation ledger，禁止一镜多付费重放
- 15s 分段 → 对齐单元时长硬校验

**不可吸收**

- “平台角色库自动锁脸”作为软件承诺（只能保证引用闭包）
- 网页一键出片 skill 作为正式路径

强项：

对本项目：

- **生成 pack 文案层**应借鉴其 shot card 字段与 continuity block 重复策略（U7）
- **不要**把模型专有 syntax 写死进 Core schema；应作为 prompt 模板或 Skill 输出

### 2.3 无限画布与规模性能（软件侧最相关）

#### tldraw Performance（官方）

要点：

1. **Viewport culling**：屏外 `display:none`，万级 shape 只画视口内
2. **Signals + batched store**：局部重绘、批量一次通知
3. **getEfficientZoomLevel**：缩放中稳定 zoom，防 jank
4. **LOD + asset resolve(steppedScreenScale)**：缩小时降分辨率图
5. **maxShapesPerPage** 默认约 4000；需更大要显式配置
6. 避免 shape 连续动画；几何缓存

对本项目 P8：

- 产品选择是 **分页驾驶舱** 而非纯 tldraw 自由白板承载 4330 宫格——正确
- 若中央区仍用 VueFlow：必须 **只挂当前 unit 的 ≤6 节点**，单元树用虚拟列表
- 缩略图 resolve 应按显示宽取 CAS 派生尺寸（P5 已有缩略图能力）
- `canvas-scale-performance` skill 已写入项目

#### prompt-to-canvas

Excalidraw 可编辑示意板：适合架构图、产品说明、分镜意图板。  
**不是** Studio 生产真相源；已下载供内部沟通。

#### VueFlow（本项目已依赖 `@vue-flow/core@1.48.2`）

社区没有“短剧专用 VueFlow skill”。实践建议：

- only-render-visible / 拆离重节点
- 节点 data 只放 ID + 摘要，媒体 URI 懒取
- 边数量随当前 unit 绑定，不做全季 graph 一次展开

## 4. 映射到 P8–P10 的可执行启发（仅记录，本轮不实现）

### P8 驾驶舱

从社区吸收的是 **信息架构** 不是代码：

- 左：季/集/单元树 + 异常队列（≈ ambiguity/missing/stale/conflict/rework）
- 中：当前 15s 2–6 宫格
- 右：BindingSet / 锁 / 连续性 / pack / result / Review
- 底：Core nextAction

性能：tldraw 的 culling/LOD 思想 + 本项目分页硬上限。

### 生成 pack schema（P8 后 / 未来 imagegen）

建议字段（文案层可参考 visual-skills shot card）：

- identity block（资产 ID、version、SHA、locks）
- continuity block（九字段 + prev raw）
- action / framing / light / sound
- negatives（多格、字幕、水印）
- parameters **外置**

### Review / 漂移

采纳五级接受报告结构进 UI 文案与 MCP 摘要字段命名，不改变 P7 存储模型。

### P9

社区无银弹；继续按交接：写入口故障矩阵、ledger 去 O(n²)、冲突查询下推 DB。
