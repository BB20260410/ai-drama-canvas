## 先说清楚：做完全量后你会得到什么（大白话）

| 阶段做完 | 你日常会感到 |
|----------|----------------|
| **P0** | 打开不懵、能拖绑资产、宫格能裁开、能「重拍」、能先待接受再进正片、能出一小段可播 |
| **P1** | 剧本拆格字段专业、绑定不会跨集乱指、提示词可外置改、能挂第二种引擎接口 |
| **P2** | **整段 15 秒单元能一键出带字幕的成片**；能续镜；能整集拼+响度正常 |
| **P3** | 脸/角色漂不漂机器能打分；资产版本清楚；风格词少出字 |
| **P4** | 画面上画圈批注、AB 对比、意见能变「返工」、能出审片报告 |
| **P5** | 上千格不卡、小地图顺、新图自动落在看得见的地方 |
| **P6** | 崩溃可续、任务可取消、探索草图不污染正式片 |
| **P7** | 多轨剪一点、导出 OTIO/PDF/工程包、未用素材能报告 |
| **P8** | 长小说拆得动、节拍模板、拆格质量可回归测试 |
| **P9** | 发布前检查、外挂上传、备份/MCP 健康 |
| **P10** | 可选实验（实时草图等）；**明确永不做**的也写死（CRDT/Comfy 正式链/浏览器供应链） |

**整 goal 最终完成** ≈：个人用「从小说/剧本 → 硬锁资产 → 分镜宫格 → 生图审片 → 配音成片 → 导出/备份」一条龙都好用，且账本仍严。  
**不等于**：云协作 SaaS、一句话全自动无审片、或公开发布商店版。

## 为何之前不「直接全量」——用大白话说

| 原因 | 说明 |
|------|------|
| **不是清单不全** | P0–P10 方面早就写在优先级表里 |
| **是执行默认范围** | 旧 goal 默认只跑切片 A，怕一次做几月、验证变假、上下文压死后忘做到哪 |
| **全量仍然要分 Phase** | 不是不做后面，而是必须先 P0/P2 出片门，再堆导出/性能；否则容易「导出很炫但每天还是白板」 |
| **你现在要的** | 一份合同写死：**goal 完成 = 全表处理完**，不是「好用一点就收工」→ 即本文 |

全量现实预期：按严格六关，往往是**数周级**长任务（跨多会话靠 STATUS/TASKS），不是一个下午。但提示词目标已经是全集。
