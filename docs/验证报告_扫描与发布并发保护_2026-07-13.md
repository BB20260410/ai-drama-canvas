## 结论

本轮修复了“扫描器在生图、下载或 FFmpeg 仍写文件时，把部分输出当作真实素材”的竞态：

- 持久扫描与 `PublicationIntent` 预留使用同一项目级 `publications` 跨进程锁；
- 扫描先开始时，新的发布预留等待扫描完成，不能在候选发现与机械验收之间插入半成品；
- 发布先开始时，扫描读取一致的 reserved 路径快照，并跳过这些目标；
- `scanStats.reservedPublicationFilesSkipped`、MCP 进度、`get_progress`、统一快照和桌面扫描提示都会公开跳过数量；
- 发布进入 registered、failed 或 cancelled 后，下次扫描不再因预留状态过滤，而是按真实文件与命名规则重新判断；
- 发布侧车损坏时，持久扫描失败关闭并保留上一份完整 JSON/SQLite/审计快照；只读导入预检不创建锁，但返回明确警告；
- `get_capabilities.scan` 公开 `reservedPublicationTargetsExcluded` 与 `publicationReservationLock`。

## 真实扫描与后台成片并发

运行命令：

```bash
npm run scan:render-contention-smoke -- \
  /tmp/ai-canvas-scan-render-contention-20260713 \
  docs/evidence/scan-render-contention.metrics.json \
  24
```

夹具真实创建 24 个生产单元、24 段 1280×720 H.264 视频，再建立 24 片段剪辑工程并后台导出 36 秒成片。FFmpeg 已创建输出后立即启动带 SHA-256 的扫描，结果：

- 基线扫描：48 个候选，48 项新检，116 ms；
- 并发扫描：发现 49 个文件、保留 48 个候选、跳过 1 个 reserved 成片输出；
- 扫描器内部耗时 151 ms；扫描调用与等待发布回执的墙钟耗时 1,496 ms；
- 写入中的成片没有进入素材索引；
- 后台成片成功，尺寸 1280×720、时长 36 秒、大小 18,676,028 bytes；
- 成片形成匹配的 PublicationReceipt；
- 终态重扫复用 48 项机械检查，写入中跳过数恢复为 0；
- 最终 `runtimeResources` 无活动扫描、活动成片或 blockedActions，项目锁为空。
