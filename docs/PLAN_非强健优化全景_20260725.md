# 计划方案 · 非「代码强健」向优化全景（2026-07-25）

> **定位**：在 P0–P14 / 双轨 L5 / 多媒体 OS / 残留清账 **已关账** 的前提下，  
> 规划 **不重复堆健壮性** 的下一阶段工作：内容一致性、提示词合同、导演体验、性能默认、产线运营。  
> **北星**：`docs/GOAL_双轨_生图与画布互补契合.md`  
> **进度**：立项后写 `STATUS.md` / `TASKS.md`；本文件是方案权威，未立项不自动续跑。  
> **禁句**：formal PASS ≠ 产品 100% 契合；不承诺永不漂。

## 1. 目标与成功标准

### 1.1 一句话目标

让无限画布从「账本可信的生产 OS」升级为：**代理生图离不开的一致性辅助台 + 导演愿意每天打开的剧本驱动工作台**——用 **提示词合同、锁参考、看板、默认快路径** 抬片质与吞吐，而不是再开一轮门禁重构。

### 1.2 整包完成门（可勾选）

同时满足才可称本方案「阶段完成」（非整仓产品终局）：

1. **Brief 合同**：隔离工程上 ≥1 单元，freeze 包内 brief/提示结构符合模板；controlRefs≥1 可审计  
2. **风格/负向库**：工程内风格锁 + 负向提示词落盘，并被 unit-grid 路径引用（或明确注入点）  
3. **导演看板 v1**：图文 covered/missing + 锁参考覆盖率（或等价只读投影）可一键查  
4. **性能默认**：UI/列表/earliest 文档与代码路径 **默认 fastMode**；full 仅诊断入口  
5. **红线**：不写 dudu-s1e1 / codex 正式 PASS；不重建平行剧本库/时间线  
6. **证据**：每阶段 JSON/MD 新文件名落 `docs/evidence/`

### 1.3 非目标

- 自动 Review PASS / 「AI 保证不漂」  
- 替换 Codex 主供应或绕过 formal 环  
- 自由无限白板、剪辑台 NLE

## 6. 提示词体系详细规格（W1 核心附录）

### 6.1 风格锁（STYLE_LOCK）示例结构

```yaml
id: style-r-cine-v1
look: "photoreal cinematic, controlled contrast, natural skin"
aspect: "9:16 or 16:9 per project"
forbidden_in_raw:
  - on-image subtitles
  - multi-panel collage
  - watermark / logo
  - redesigned face vs refs
```

### 6.2 身份锁（IDENTITY_LOCK）

- 每角色：**≤40 字身份句** + **≤3 张 controlRefs**（脸/服/全貌）  
- 禁止仅靠长文本顶替已有权威图  
- 黄金面具等硬锁：SHA 写死，禁止半面具变体（既有 AGENTS 规则）

### 6.3 节拍（BEATS）

| 格 | 必填 |
|----|------|
| 景别 | ECU/CU/MS/WS… |
| 运镜 | 固定/推/拉/摇…（可引用 cinematic skill） |
| 动作 | 可见行为 |
| 情绪 | 可选 |
| 秒数 | 总和 ≈15s |

### 6.4 续镜（DELTA_ONLY）

- 源图已表达的脸/服/场景 **不复述**  
- 只写：动作变化、机位变化、光色变化、终点状态  
- I2V 立项时直接复用本节，不另起标准

### 6.5 Review 映射

| criteria code | 导演语言 | 机器辅助 |
|---------------|----------|----------|
| hard-lock | 硬锁图是否像 | 四态/人工 |
| identity-consistency | 是不是同一个人 | 四态 |
| prop-costume | 服化道 | 人工为主 |
| scene-continuity | 场景是否接 | 人工+四态 |
| prompt-contract | 是否按节拍 | 人工 |
| image-quality | 能否用 | 人工 |
| forbidden-content | 禁项 | 人工 |
