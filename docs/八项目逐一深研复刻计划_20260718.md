## 1. 硬原则

### 1.1 什么叫「研究透彻」（Phase R 完成门）

对**当前项目**，下列证据齐才可写「研究完成」：

1. **固定 pin**：default branch HEAD SHA + 最新 release tag（若有）  
2. **LICENSE 全文** + 个人/商用边界（个人向仍记录）  
3. **目录地图**：前端 / 后端 / DB / 画布 / 生成链路入口文件路径表  
4. **核心用户路径 1–3 条**：从「导入/建项」到「出图/出片/画布操作」跟到具体函数  
5. **数据模型**：项目/角色/场景/分镜/媒体表或 JSON 字段 ↔ 本库 owner 对照  
6. **可吸收功能表**：每条标 `TAKE / ADAPT / SKIP`  
7. **不做清单**：为何跳过（第二真源 / 红线 / 与本库重复 / 维护成本）

**研究方式（允许加深）**

- 默认：GitHub API + raw 源码页（树 + 关键文件）  
- 若页面不够：**shallow clone 到仓库外隔离目录**  
  - 例：`~/Documents/_ref-study/<name>-<sha>/`  
  - **禁止** clone 进 `无限画布/` monorepo  
- 可本机 `npm run` / docker **对照运行**（数据不写 `projects/codex-ai-drama-studio`）  
- **禁止**：install 后把对方 DB/素材导入正式空库  

### 1.2 「复制 / 复刻」等级

| 等级 | 含义 | 何时用 |
|------|------|--------|
| **L0 对照** | 只跑对方软件，写笔记 | 一切项目 |
| **L1 合同复刻** | 字段/状态机/交互合同，本库自写 | **默认** |
| **L2 依赖引入** | 正式 npm 包（MIT/Apache） | Vue Flow 类 |
| **L3 受限搬运** | 短算法/布局公式，保留 NOTICE、不整仓 | 仅 LICENSE 允许且价值极高 |
| **禁止** | 整库 merge、第二 SQLite 真源、AGPL 核心并入、社交发帖链 | 始终 |

本库真源：**CAS + SQLite + `execute_command`**；画布/列表只是视图。

### 1.3 红线（不变）

- 不重建 P0–P10 owner；不覆盖 `final-validation-*`  
- 不 Git stage/commit/push（无 owner 书面授权）  
- 不 Artlist/浏览器正式生图；正式生成面仍 `agent-imagegen`  
- 不污染 `projects/codex-ai-drama-studio` 空库  
- 不把 TwitCanva 的发 X/TikTok 合入  
- 不替换既有正式生图供应商哲学

## 2. 单项目执行节奏（串行循环）

**一个开源项目 = 一条完整产线**，做完再下一个。

```
Phase R  深研（研究包落盘）
   ↓
Phase S  选型（最多 1–3 个 TAKE/ADAPT，本项目内最高 ROI）
   ↓
Phase I  实现（扩展既有 owner；isolation fixture）
   ↓
Phase V  验证（typecheck + 定向 vitest + 能跑的 smoke；正式库业务 COUNT=0）
   ↓
Phase C  关账（evidence + STATUS/TASKS 勾选「该项目完成」）
   ↓
下一项目
```

### 2.1 每项目交付物（磁盘强制）

```
docs/ref-study/<seq>-<slug>/
  00_研究完成报告.md
  01_功能对照表.md
  02_实施切片.md
  evidence/
    research-<slug>-<date>.json
    absorb-<slug>-<slice>-<date>.json   # 仅已实现的切片
```

| 全局文件 | 作用 |
|----------|------|
| `STATUS.md` | `当前项目` / `当前 Phase` / 执行者 / 下一步唯一动作 |
| `TASKS.md` | 八项目 checklist + 每项目 R/S/I/V/C |
| 本文 | 权威总计划 |

### 2.2 单切片完成门（Phase V 必须真跑）

- `npm run typecheck` 绿  
- 触及模块的 vitest **驱动真实函数/入口**（禁止假测）  
- 新 evidence **不覆盖** final-validation  
- 正式工程业务表 COUNT=0（排除 FTS/meta）  
- STATUS 写明「可开始下一项目」  

**未测通：不进入下一开源项目。**

### 2.3 六维完成门（关账前自审）

| 维度 | 问什么 |
|------|--------|
| 机械 | 文件/SHA/测试绿？ |
| 功能 | 正式入口可达、状态机正确？ |
| UI | 真路径打开过？或结构测+降级说明？ |
| 性能 | 目标规模？还是小样本？ |
| 视觉/一致性 | 有标准？还是脚本写死 pass？ |
| 外部真实 | 真 API？还是本地伪造？ |

任一未做 → 结论最高 **部分完成**，禁止「已完成关账」。

- 若 0 个 TAKE：写 SKIP 理由 → **直接 Phase C 关账**（研究完成也算完成）→ 下一项目

## 4. 单项目深研清单模板（复制用）

### Phase R — 研究

- [ ] pin SHA/tag + LICENSE 落盘  
- [ ] 画目录树（前后端/DB/画布/生成）  
- [ ] 跟踪路径 A：新建项目 → 剧本/分镜 → 出图  
- [ ] 跟踪路径 B：画布操作（拖/框选/组/生成）若适用  
- [ ] 数据表/JSON ↔ 本库 material-studio / production / generation / dashboard  
- [ ] 输出 `00_研究完成报告.md` + `01_功能对照表.md`  
- [ ] 评审：本项目 **最多 3 个** TAKE/ADAPT  

### Phase S — 选型

- [ ] 排序：用户价值 × 与目标对齐 × 接入成本 × 许可风险  
- [ ] 写 `02_实施切片.md`（文件清单 + 验收命令）  
- [ ] 0 TAKE → SKIP 理由 → 关账进下一项目  

### Phase I — 实现

- [ ] 只改约定 owner 文件  
- [ ] isolation/tmp 或现有 fixture，不碰正式空库  
- [ ] clean-room 优先；L3 须报告文件哈希 + NOTICE  

### Phase V — 验证

- [ ] typecheck + 定向测试（真路径）  
- [ ] 可选 UI smoke；Electron 起不来则结构测 + core 测 + 降级说明  
- [ ] 正式库业务表 COUNT 日志  

### Phase C — 关账

- [ ] evidence JSON（新文件名）  
- [ ] TASKS 勾选「项目 N 完成」  
- [ ] STATUS：`下一项目 = N+1`，当前 Phase 清空或指向下一 R

## 6. 时间与额度（不惜成本时的默认排期）

| 阶段 | 单项目粗算 | 说明 |
|------|------------|------|
| R 深研 | 0.5–2 人日 | LocalMiniDrama / LumenX 偏长；OpenCut 可能很短 |
| S+I | 0.5–2 人日 | 每项目 ≤3 切片 |
| V+C | 0.25–0.5 人日 | 硬门禁 |

八项目串行 **大约数周量级**；可压缩但**不可跳过 V**。

### 6.1 会话策略（解决「老停」）

每会话开工写死完成门，例如：

```text
本会话完成门：LocalMiniDrama 的 R+S 完成并落盘 00/01/02；
若 S 有 TAKE，继续 I+V 至少一个切片测绿；
未达完成门禁止只写「下一刀」。
```

压缩前：STATUS 必须反映真实进度；压缩后以磁盘 STATUS/TASKS 为准。
