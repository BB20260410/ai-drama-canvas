### 2.4 媒体拖出复制体

- Core 在 owner 范围内重新解析媒体，校验 SHA、大小、MIME 与扩展名。
- 使用 `copyFile` 生成独立文件；拒绝符号链接，不使用硬链接。
- 导出后再次解析源文件并校验复制体 SHA / 大小，源 CAS 保持不变。
- Renderer 只获得短期一次性 UUID token，不获得 CAS 路径或临时绝对路径。
- token 绑定 sender webContents、project、SHA 和过期时间；Main 复核文件身份后调用 `startDrag({ file, icon })`。
- 图片、视频、音频均提供非空拖拽图标。
- 只有具有唯一真实媒体身份的节点显示“拖出复制体”手柄；借用缩略图的 panel 不显示。
- 画布媒体库支持 all / image / video / audio、搜索和 36 条分页；最多固定 12 个真实媒体节点。

## 5. 另行定位：`viewport` 布局保存冲突

截图提示“画布布局并发修改冲突，未覆盖任何一方：viewport”表示本次缩放 / 平移状态未保存，素材本体没有删除。

当前保存逻辑存在单窗口也可触发的竞态：前一次 CAS 写入成功后，如果期间又产生新的 viewport generation，前一次成功结果不会更新本地 fingerprint / base；下一次保存会把自身上一笔远端写入误判为另一方修改，最终触发三方合并冲突。

该缺陷本轮仅完成诊断，**没有修改布局冲突策略**。后续修复应将保存改为单写队列并合并最新 viewport；真实跨窗口的节点、固定媒体和连线冲突仍保持 fail-closed。
