# 单元复盘闸门（Unit Retro Gate）· 2026-07-23

> **硬规则：** 每完成一个 formal 单元（Un），**禁止**立即把 earliest 写成 Un+1 并开干。  
> 必须先走完 **R0–R4**，STATUS 写 `unit_retro: PASS` 后，才允许 A earliest = Un+1。

## 目的

把「生图 × 无限画布」每一步都变成可改进循环：找不足 → 修 → 验无阻塞级 BUG → 再下一 U。

## 流程（每个 formal 单元后）

| 步 | 动作 | 产出 |
|----|------|------|
| **R0** | formal 证据齐（report + raw/labeled + orderProof） | `s1e2-uNN-symbiosis-report.json` |
| **R1** | 多代理复盘（≥2 角：产线合同 / 一致性与产品） | `05_canvas/retro-uNN-YYYYMMDD.md` |
| **R2** | 合并缺口清单，自决优先级（P0 本单元必修 / P1 可记债） | STATUS「本单元缺口」 |
| **R3** | 修 P0 + 真实验证（测/复跑相关路径） | 代码或脚本 + 验证记录 |
| **R4** | `unit_retro: PASS`；`b_skip_streak` 合理；earliest → Un+1 | 写盘 STATUS/TASKS |

## 复盘维度（强制覆盖）

1. **合同链**：readiness→freeze→dispatch→prepare→gen→commit；租约/mcp-only/WAL  
2. **一致性辅助**：controlRefs 是否真约束 gen；Binding/角色·场景·站位  
3. **产品环**：与剧本/earliest/审片/SSL 的缺口  
4. **稳定性**：失败重试、token、并发、假关账  
5. **表述**：是否出现 formal=契合 等禁句  

## 完成定义

- P0 缺口全部修完或有可复验 workaround 且 STATUS 登记  
- 无新引入阻塞级 BUG（相关路径至少跑通一次）  
- retro 文件落盘  

**不要求** 每单元都做到 L5；要求 **不带已知阻塞级缺陷冲下一 U**。
