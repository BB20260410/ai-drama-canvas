# 残酷缺口审计（落盘版）

> 来源：explore 子代理 2026-08-02 只读审计；本文件为正式落盘。

## A. 一句话

**今天软件是「Agent 写章机械 OS + 人读编辑器」，不是「像外部 STATUS/角色状态.md 那样能带多 AI 跑百万字不崩的写书工作台」。**

## 四表

1. **已有且可用**：正文 CAS、Writing OS MCP 主路径、Pack 2.0 预算/cutoff、writing-state 八项+知情、preflight 指纹、状态候选人工门、1M smoke、加固 CLEAN。  
2. **有合同未产品化**：状态/Pack/preflight/审稿/候选在 NovelStudio **零 UI**；preload 未暴露；验收 Oracle/RP/分文件 bible 未收口。  
3. **一致性致命缺失**：外形声口 Authority、禁揭扫描、object-injury、自动状态差、人机分叉灯、多 AI 席位、全书 STATUS 投影。  
4. **错误方向**：聊天正典、自动 commit、一键全收、绕过 preflight、双 owner、灌整本上下文、假关账文学分。

## 裁决

| 问题 | 裁决 |
|---|---|
| 今天能帮 AI 到什么程度？ | 脚本化/MCP 单章闭环：能。桌面辅助多 AI 长程：不能。 |
| 人物一致性？ | 有截止投影与指纹门；无外形声口硬锁、无禁揭扫描、无伤势道具账、无 UI 状态审片 → 跨模型仍漂。 |
| 百万字不崩？ | 存得下；一致撑不住（状态维护与人机门未闭合）。 |
| 画布 UI vs MCP？ | MCP=OS；UI=记事本。下一步把 OS 暴露为驾驶舱。 |

**优先级一句话**：先做「看得见的 STATUS + 状态 commit 面 + 禁揭/声口硬槽 + 堵人类分叉」，再谈智能与百万字美学。
