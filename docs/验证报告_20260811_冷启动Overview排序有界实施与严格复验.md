## 6. 阻塞根因与下一唯一切片

直接测试阻塞：

- 单元节点数据为 `data.id=unit.id`。
- 作用域化观察器查找 `data.unitId`。
- 因字段不一致，`canvas-first-card-dom-unit:<unitId>` 永远不产生。

实际性能阻塞：

- `canvas-units-ready=1917.2ms`，比 1500ms 严格预算晚 417.2ms。
- `app-project-activation-ready=2397.4ms` 晚于 units ready；当前缺少 activation start 里程碑，尚不能证明它与 units 重叠或构成因果，只能把它作为下一步最值得验证的单一竞争假设。

如果继续，只开启 `PERF-FIRST-COLD-ACTIVATION-01`：

1. 给单元节点补齐 `unitId: unit.id`，并增加 activation start 里程碑；不改变业务结果。
2. 先证明 activation 是否真实与 units 重叠及其耗时贡献；只有证据成立，才验证“冷恢复且已经是同一活动工程”时能否延后到首卡之后。显式切工程仍保持原有同步 activation 合同。
3. 产生一个新 sourceDigest，只运行一次新的隐藏严格 T23。
4. 不再修改 Schema cache、Overview 排序、模块预热或 Core Dashboard。
