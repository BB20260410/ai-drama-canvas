## 实际改动

### 1. Review 历史 latest-only

- Review 当前条目的历史读取使用独立 project-scoped request gate。
- 快速 A→B 选择时，A 的迟到成功或失败均不能覆盖 B；卸载会使旧请求失效。
- 不改变 Review 提交、审批或事实源合同。

### 2. Projection 请求级资产去重

- canonical asset 读取改为单请求 Promise cache，并发上限 4。
- 同一资产在六宫格重复引用时只读取一次；每个 panel 的输出顺序、失败传播、stamp 与顶层 fingerprint 保持不变。
- 诊断增加 `canonicalAssetReadCount`，不进入业务 fingerprint。

### 3. npm 生产依赖语义门

- candidate 与 isolated package 两条链共用同一 `npm ls --omit=dev --all --json` 语义门。
- 同时解析 `problems` 和节点 `extraneous/missing/invalid` flags；按真实 `node_modules` 路径、lockfile Node resolution、逐边版本范围和 installed exact version 验证。
- 未知、missing、invalid、路径错配、同名 nested 版本错配及 prerelease 范围误匹配全部失败关闭。
- 实时工作区只接受三个 lockfile 可证明的 sharp optional WASM 项，无 rejected problem。

### 4. SQLite busy 与绝对截止

- 原始 `SQLITE_BUSY/LOCKED` 不再被当作整条命令零副作用证明；只有带 typed proof 的 pre-domain 或完整回滚错误可重试。
- command ledger 初始登记直接以 `executing` 同事务落盘，消除 `running/registered` 卡死窗口。
- 已有文件/数据库副作用后再遇 raw busy 会进入 `unknown`，禁止自动重放。
- command 与 project backup 都把单次 SQLite lock timeout、退避和总执行绑定到同一个 5 秒 absolute deadline。
- 真实 `BEGIN IMMEDIATE` 锁竞争在有界时间内失败关闭，备份 staging 清零。
