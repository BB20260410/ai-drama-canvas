## 实际实现

### 1. 正式分镜安全局部修订

- `upsertStoryboardRow` 对已有镜头强制要求 `expectedRevision`，只合并调用方明确提交的字段。
- 顺序、时长、景别、机位、焦段、构图、运镜、人物调度、动作、表情、情绪、视线、屏幕方向、轴线、对白、旁白、环境音、音效、前后连续性、导演意图、情绪意图、来源证据、事实/节拍引用、参考名称/路径/素材 ID 和生图/视频提示词均进入同一合同。
- 新建镜头仍运行必填字段、6 镜/15 秒、证据和引用门禁；已有镜头可安全局部修改。
- 桌面“生产设计 → 正式分镜表”提供完整逐镜编辑器；只修改对白后，26 个其余导演合同字段逐项保持一致，关闭并重启应用后仍一致。
- MCP 命名工具和 `execute_command(upsert_storyboard_row)` 使用同一个补丁 Schema，没有建立第二套写通道。

### 2. 视频续接统一 GenerationJob 状态机

- 时间线续接和源视频末帧续接都必须绑定唯一 GenerationJob；重复入队会在产生外部副作用前被拒绝。
- 时间线合成首帧标记为 `timeline_continuation`，源视频提取首帧标记为 `video_continuation`；二者都把已登记、可解码、冻结校验值的图片放入 `first_frame` 槽位。
- 续接包只投影关联任务的状态：`queued → preflight → uploaded → submission_unknown → submitted → processing/downloaded → completed`，以及 `failed/cancelled` 终态。
- 点击可能付费的网页提交前，必须先持久化 submit intent 和 `clientJobId`。中断后任务与续接包同时保持 `submission_unknown`；独立 Node 进程重启后仍可读取，队列不会自动重提。
- `update_video_continuation` 只允许带 `expectedRevision` 和真实原因终结尚未入队的包；已绑定包禁止手工写 submitted/completed。
- 网页下载结果先进入隔离目录，验证魔数、尺寸/时长、可解码性和 SHA-256，取得 PublicationReceipt 后，GenerationJob 与续接包才投影为 verified/completed。
- Doctor 会明确报告未入队续接包、提交结果待对账、投影漂移、缺失 GenerationJob 或缺失续接包，并把对账置于继续生产之前。

### 3. Codex 契约与项目登记可靠性

- `execute_command` 补齐小说分析 Provider 的配置、执行和批量审核三个命令 Schema。
- `enqueue_generation` 的命名工具与统一命令 Schema 都接受结构化 `continuation`。
- `continue_video_from_last_frame` Prompt 已改为完整的 GenerationJob/网页检查点/对账链路，不再指示 Codex 独立回写续接包。
- `list_projects` 变为真正只读：项目根暂时离线时返回 `available=false` 和原因，不会悄悄从注册表删除；桌面项目中心保留并禁用该条目。

### 4. 分数帧率整数帧剪辑

- 时间线交互按工程有理时间基计算，不再固定保留三位小数后等待保存阶段纠偏。
- 播放头 range 步长等于 1 帧；拖动、左右裁切、吸附、主轨重排、关键帧、分割和 Ripple 都量化到整数帧。
- 23.976 工程显示 `24000/1001`、绝对帧号和 `时:分:秒+帧`；片段显示真实帧数。
- 核心分割/裁切门禁从固定 0.02 秒改为至少距离边界 1 帧；Ripple 在所有未锁定轨道上比较和移动整数帧，避免长时间线累计漂移。
- Electron 真实运行把 F12 作为分割点，落盘主轨为 `0+12f、12+36f、48+48f`；Ripple 与撤销后仍保持连续，1280×760 无页面溢出。
