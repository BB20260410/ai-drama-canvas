## 2. 实现合同

### 2.1 独立适配与提交恢复

- `GenerationAdapterType` 新增 `comfyui-local`，只允许 loopback origin，首版只执行图片。
- API-format workflow 必须显式配置 prompt 输入、唯一输出节点与输出索引；任务入队后冻结供应商、工作流、参数和执行快照。
- 任何 POST 前先持久化 canonical UUID `promptId`、稳定 `clientId`、attempt、原工作流/物化工作流 SHA-256、输出绑定和请求文件。
- `prepared + !postAttemptedAt` 重启继续使用同一 attempt/promptId；暂态 preflight 网络错误、408/425/429/5xx、坏 JSON或响应上限错误保持 reserved/prepared，确定性 4xx、工作流或 class 不兼容才在提交前闭合失败。
- POST 回执断连进入专属 `submission_unknown`；fresh Node 只查询同一 promptId，不能合成 HTTP checkpoint，也不能重 POST。

### 2.2 官方 prompt tuple、history 与输出身份

- queue/history 必须提供官方 prompt 5-tuple，并同时匹配 tuple promptId、物化图哈希、clientId、`extra_data.aicanvas` 的 generationJobId/clientJobId/attempt/工作流/输出标签和 `outputs_to_execute`。
- history 只接受同 promptId 的 exact `execution_success`、`execution_error` 或 `execution_interrupted`；自由文本包含事件名、矛盾终态、history SHA 漂移或非目标条目均保持锁定。
- 成功输出严格绑定 `promptId + outputNodeId + outputIndex + filename + subfolder + type=output + historySha256`；路径必须安全，随后经过每任务隔离下载、完整解码、SHA-256 与不可覆盖 Publication。
- 失败/取消必须先把匹配 checkpoint revision 的 exact history 或原子取消响应证据写入 Job，再用同一来源关闭 Publication；并发 `registered` 永远优先。

### 2.3 原子取消

- 产品路径只调用 `/api/jobs/{promptId}/cancel`；旧 `/queue delete` 与 `/interrupt` 的调用数必须为 0。
- pending 只有在服务端 `cancelled:true` 且 queue/history 连续两次稳定 absent 后才关闭。
- running 即使服务端 acted、随后暂时 absent，也仍保持 Job/Publication 锁定，必须等同 promptId 的 exact `execution_interrupted`。
- `cancelled:false`、503、坏响应、未知状态或成功/registered 竞态都不会制造本地假取消。

### 2.4 可观测性与桌面端

- Capabilities、Doctor、Snapshot、Generation Resource、Continuation/恢复 Prompt、命令账本和 MCP 摘要均区分 Browser、HTTP、ComfyUI 检查点并保持 URL、提示词和凭据脱敏。
- 桌面供应商设置可配置 loopback 地址、API workflow、prompt 绑定、输出节点/索引并显示工作流 SHA；任务行显示 `queued/submission_unknown/verified`、checkpoint revision、promptId 和已验证输出身份。
- WebSocket 仅作为未来进度增强，不是终态事实源。
