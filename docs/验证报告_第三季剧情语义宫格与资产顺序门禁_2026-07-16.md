## 1. 本轮解决的真实缺口

### 1.1 宫格曾按 row 数机械取格

旧合同把一个 8–12 秒主镜内的多个明确秒点与动作转折压在同一格；显式增格还会重复整段动作或使用“段内转折时刻”占位。这不满足用户要求的“根据剧情思考 2–6 格、详细中文版本”。

本轮新增 `semantic-beat-v1`：

- 识别中文强标点、动作转折和“第 N 秒”时间锚点；
- 镜头/运镜描述前缀不伪造成剧情格；
- 纯延展段固定为一格，不新增剧情事件；
- 每格保存独立中文动作、节拍索引、时间段、来源 row/原镜/资产与唯一生图提示词；
- 超过六个节拍时连续透明归并，row 与 15 秒 schedule 仍完整覆盖；
- 算法版本进入 contract ID 和 UI 幂等键，旧机械合同不能被当前 UI 回放。

### 1.2 text-only 资产无法进入 submit_intent

18 项 EP01 新资产合同均为 `authorityReferences=[]`。旧状态机允许 `uploaded(files=[])`，但提交前又错误要求至少一项文件，导致即使额度恢复 P01 仍会本地死锁。

修复后：

- 空白名单必须显式提交 `uploadEvidence={files:[]}`；
- 保存 `expectedFileCount=0`、`uploadRequired=false`；
- 非空白名单仍严格核对数量、路径、role、order、SHA 和当前文件哈希；
- 正式 P01 隔离克隆已完成 R2 → R3 preflight → R4 uploaded([]) → R5 submission_unknown 的本地状态机烟测；
- 烟测没有打开浏览器、点击 Generate、产生 remote identity、下载结果或 Publication receipt；正式四侧车 SHA 前后不变。

旧六张门禁只限制每批最多六项，不能阻止用户先入队后出场资产。
