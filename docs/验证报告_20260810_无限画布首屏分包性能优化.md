# 无限画布首屏分包性能优化验收

## 结论

本轮有界性能改进已完成。旧版生产画布的 VueFlow 运行时、背景/控制器以及 6 个旧画布组件不再静态进入所有工作区的首屏主包；项目中心、小说工作区和受管工作区不会先解析一套当前用不到的旧画布代码。

正式无窗口构建实测，renderer 主 JS 从 **807,753 B** 降至 **437,455 B**，减少 **370,298 B（45.84%）**；gzip 后从 **175,471 B** 降至 **98,418 B**，减少 **77,053 B（43.91%）**。

## 原因与改动

`App.vue` 虽然已经把多数业务视图动态加载，但仍静态导入 `@vue-flow/core`、background、controls 和 Production/Zone/Note/Group/Narrative/Inspector 组件。这使不进入旧版画布的路径也承担其下载、解析和初始化成本。

本轮将这些依赖改为 `defineAsyncComponent`，并用 VueFlow 的 `pane-ready` 事件保存实际挂载后的 store。诊断缩放、视口快照和节点聚焦在画布尚未挂载时安全返回，不再依赖根组件初始化时调用 `useVueFlow`。

## 机械验收

| 项目 | 改前 | 改后 | 结果 |
|---|---:|---:|---:|
| 首屏主 JS | 807,753 B | 437,455 B | -45.84% |
| 首屏主 JS（gzip） | 175,471 B | 98,418 B | -43.91% |
| 全部 JS 总量 | 2,930,500 B | 2,938,658 B | +0.28% 分包开销 |
| VueFlow core | 静态包含在主包 | 335,377 B 独立懒加载块 | PASS |
| HTML 静态预加载 VueFlow | 是（随主包） | 否 | PASS |

全部 JS 总量略增 8,158 B 是动态分包包装开销；关键收益是未使用旧画布时不再支付其 335 KB 级运行时代价。

- 影响范围复验：4 files / 42 tests PASS，覆盖旧画布分包、小说路由、剪辑离开门禁和受管画布 UI 合同。
- `npm run build` PASS：两套类型检查、MCP build、构建身份和 Electron renderer build 全部成功。
- `git diff --check` PASS。

## 边界

- 本轮没有打开 Electron 窗口，没有写正式项目、素材、CAS 或 SQLite。
- 这是首屏下载/解析热路径的确定性优化，不等同于宣称所有类型的运行时卡顿都已消失；未做带窗口的冷启动计时。
- 真正进入受管无限画布或旧版画布时，VueFlow 仍会按需加载，因为该视图确实需要它。
- `/Applications/AI 漫剧画布.app` 未被替换；本轮只更新源码、正式构建产物和构建身份，没有打包、签名、公证或安装。
- 未执行 Git stage、commit 或 push。
