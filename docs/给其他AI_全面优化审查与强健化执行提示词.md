# 给其他 AI 的全面优化、审查与强健化执行提示词

更新时间：2026-08-12

## 使用方法

- 新任务先把下面“主提示词”整段发给执行 AI。
- 需要聚焦某一方向时，再追加文末对应专项词，不要同时开启多个写代码窗口。
- 本文件是执行模板，不是项目状态真相源。实际状态仍以 `docs/当前开发交接.md`、`STATUS.md`、`TASKS.md`、Git 与当前运行证据为准。

## 可直接复制的主提示词

```text
你正在本机仓库 `/Users/hxx/Documents/无限画布` 做一次“证据驱动、行为保持、有界收敛”的全面质量提升。不要只给建议；在权限范围内实际复现、修复、测试并更新权威交接。

一、恢复与基线
1. 先完整读取：
   - `/Users/hxx/Documents/无限画布/AGENTS.md`
   - `/Users/hxx/Documents/无限画布/docs/当前开发交接.md` 顶部最新区块
   - `/Users/hxx/Documents/无限画布/STATUS.md`
   - `/Users/hxx/Documents/无限画布/TASKS.md`
   - 与任务匹配的项目 Skill；无限画布研发必须使用 `.agents/skills/ai-drama-canvas-agent/SKILL.md`，规模性能再使用 `.agents/skills/canvas-scale-performance/SKILL.md`。
2. 先运行只读基线：`pwd`、`git rev-parse --show-toplevel`、`git status --short`、`git log -3 --oneline`、`git diff --check`。确认当前分支、已有脏改动、活跃进程和现有测试分区，不得覆盖或回退他人改动。
3. 读取当前源码和运行态，不从聊天摘要猜状态。历史 PASS 只能证明当时冻结身份，不能证明当前源码。
4. 如果工作树起点不干净，先按文件归属分类并记录；禁止 `git reset --hard`、`git clean`、`git checkout --` 或批量覆盖。

二、目标与优先级
目标是提高：运行速度、启动速度、交互流畅度、内存与 CPU 效率、稳定性、错误恢复、并发正确性、文件与 SQLite 安全、数据一致性、UI 可用性、可访问性、可测试性、可观测性、构建与交付可靠性。

发现按以下等级处理：
- P0：数据破坏、权限/密钥泄露、付费或外部副作用失控、正式工程不可恢复、应用无法启动。
- P1：核心功能失败、重复提交、退出/启动挂死、跨工程串写、可靠复现的严重竞态或安全边界绕过。
- P2：高价值稳定性、性能、UI、恢复或证据可靠性缺陷。
- P3：一般体验、可维护性与防御性改良。

先关闭 P0/P1，再做可量化的 P2；不要为了“全面”制造无收益重构。没有复现证据的问题先记为假设，不能写成已确认缺陷。

三、审查范围
至少覆盖以下真实链路，但先做风险地图，再按证据选择最小切片：
1. 启动、切工程、首次渲染、窗口关闭、Cmd+Q、崩溃恢复、watcher 与后台任务收敛。
2. 项目中心、受管画布、Material Studio、Review、生成控制、总资源、小说工作台、剪辑台、设置和导入导出。
3. 所有可见按钮、菜单、分页、搜索、筛选、键盘操作、弹窗、空态、错误态、加载态、禁用态、脏数据离开门和撤销重做。
4. Main / preload / Renderer IPC 的 effect 分类、退出 admission、latest-wins、取消、超时、迟到回填和跨 root 隔离。
5. SQLite busy/deadline、事务原子性、幂等键、failed/unknown 分类、崩溃后对账、文件 no-clobber、软链/路径逃逸、CAS 与 immutable receipt。
6. MCP 工具 ABI、source/currentness、候选发布、隔离 package、失败证据、锁释放、自然退出。
7. 小说 Provider 的 HTTPS、DNS pin、TLS、重定向、代理、凭据与正文脱敏；生成/外部调用的 intent-before-side-effect 与禁止未知重提。
8. 性能：冷启动、首卡、首 raw、全部参考、项目切换、分页、缩放/拖拽、剪辑播放、长列表、媒体预览、内存峰值、FD、CPU、长任务和后台队列。
9. 依赖、许可证、生产依赖审计、类型检查、构建身份、测试分层和 flaky/超时掩盖。
10. 可访问性：语义角色、标签、键盘焦点、对比度、缩放、错误提示和无障碍操作路径。

四、执行方法
1. 每个问题必须形成：证据 → 最小复现 → 根因 → 影响 → 红测 → 最小修复 → 定向绿测 → 相邻回归 → 结论。
2. 性能问题必须先测量再改。记录相同冻结身份、同一夹具、冷/暖状态、样本数、p50/p95/峰值；禁止用提高 timeout 冒充优化。
3. UI 必须在隔离工程和隐藏后台模式下做真实 Electron/Playwright 操作；逐个测试可见控件，并记录控制台错误、page error、自然退出和进程残留。机械测试通过不能冒充人工视觉质量通过。
4. 并发/恢复问题使用 deferred promise、真实 SQLite writer lock、故障注入、进程中止点和重启对账验证；不得仅用源码字符串断言替代行为测试。
5. 安全审查覆盖路径约束、软链、DNS rebinding、TLS 降级、HTTP 明文、敏感错误投影、凭据/正文/绝对路径泄露和外部副作用重复。
6. 只复用既有 owner、SQLite/CAS/命令总线和 Review；禁止新建平行数据库、平行状态机或第二真相源。
7. 同一时间只允许一个 writer。可并行的 reviewer 必须只读且边界不重叠；主执行者负责整合和最终证据。
8. 同一失败最多两轮同范围纠正。第二轮仍无新证据时停止原样重试，重新分类根因或登记唯一阻塞；禁止陷入循环。

五、验证顺序
按风险由小到大运行，不要一开始就重跑全部：
1. 新增/修改模块的红绿测试。
2. 相邻模块定向测试。
3. `npm run typecheck`。
4. `npm run typecheck:app`。
5. `npm run test:partitions:audit`。
6. 在源码冻结且无其他重负载进程时，串行运行 fast / medium / integration / heavy；已取得完整同身份 PASS 的分区不要无理由重跑。
7. `npm run audit:production`，只接受官方 registry 的真实结果。
8. `npm run build`，核对 live sourceDigest、release manifest、buildId 与 MCP tool count。
9. `git diff --check`、敏感信息扫描、大文件扫描、进程残留检查。
10. 只有用户明确要求安装，且上述门全部通过后，才进入 candidate → isolated package → 签名 local-only App → installed hidden verify；不公证、不发布、不付费。

六、停止条件与完成门
满足以下条件才可说“完成”：
- 选定范围 P0/P1=0，确认的高价值 P2 已修或有用户认可的明确边界。
- 所有改动都有行为测试或真实运行证据，定向/相邻测试、两套 typecheck、构建、依赖审计和 diff check 通过。
- 没有未处理的 running/unknown 账本、临时锁、测试进程、旧 App 进程或未解释的 Git 脏文件。
- 未触碰正式工程、用户权威素材、外部上传、付费、公证、发布，除非用户逐项明确授权。
- 更新 `docs/当前开发交接.md`、`STATUS.md`、`TASKS.md`，写明当前身份、已完成、未包含、实际命令和结果。
- 如果用户授权 Git：按独立逻辑切片暂存和提交；提交信息只描述实际 staged diff；不要 push，除非用户再次明确要求。

七、输出格式
先给决定性结果，再给证据：
1. 已修复的问题（P0/P1/P2、根因、用户影响）。
2. 实际改动文件和架构边界。
3. 实际执行的测试/构建/运行证据与结果。
4. 没有执行的项目及原因。
5. 当前 Git 状态、进程状态、安装版与源码身份是否一致。
6. 剩余风险只列真实、可复现或明确待授权项；没有就写“无已知未完成阻断”，不要为了显得认真而虚构问题。

默认授权边界：允许在本仓库做有界源码、测试和文档修改；允许隔离临时工程和后台隐藏测试；不允许改正式项目数据、调用付费模型、上传、删除重要证据、公证、公开发布、push 或破坏性 Git。缺少会实质改变结果的新授权时才停下来问用户。
```

## 可追加的专项词

根据目标一次追加一到两个，避免把所有专项同时塞给执行者：

- 性能：`性能剖析、冷启动火焰图、关键路径、N+1 查询、请求合并、虚拟化、分页、懒加载、缓存失效、长任务、内存泄漏、FD 泄漏、CPU 热点、IPC 往返、p50/p95、峰值约束`。
- 稳定性：`竞态条件、latest-wins、取消传播、背压、单飞、幂等、超时、绝对 deadline、SQLite busy、崩溃恢复、进程退出收敛、故障注入、soak test`。
- 安全：`威胁建模、SSRF、DNS rebinding、TLS 校验、路径穿越、软链逃逸、no-clobber、密钥脱敏、最小权限、依赖漏洞、敏感日志审计`。
- UI/交互：`全按钮巡检、键盘可达性、焦点管理、空态/错态/加载态、响应式、对比度、屏幕缩放、视觉回归、真实 Electron E2E`。
- 架构：`owner 边界、单一真相源、循环依赖、模块内聚、命令/查询分离、事务边界、错误分类、公共合同、行为保持重构`。
- 测试：`单元测试、集成测试、端到端测试、冒烟测试、回归测试、属性测试、模糊测试、并发测试、故障注入、快照身份、flaky 根因`。
- 交付：`可复现构建、供应链审计、许可证、immutable candidate、隔离打包、签名、本机隐藏验收、自然退出、回滚演练、证据 no-clobber`。

这些词不是越多越好。最有效的组合通常是：

`代码审查 + 动态测试 + 性能剖析 + 并发/故障注入 + 安全强健化 + Electron E2E + 回归测试 + 可复现构建 + 交接收口`。
