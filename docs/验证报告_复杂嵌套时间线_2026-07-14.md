## 2. 核心实现合同

### 2.1 冻结引用与显式刷新

- `EditClip.kind="timeline"` 保存子工程 ID/revision/timebase/canvas、可见源区间、约分有理 source offset/step 和 SHA-256 内容寻址快照。
- `add_nested_timeline` 由核心读取子工程并创建不可变快照；`refresh_nested_timeline` 只能显式冻结调用方指定的当前子修订。通用 `update_clip` 不能伪造权威引用。
- 内容寻址快照独立于只保留 30 项的普通 history；旧快照不会被后续保存覆盖。
- 自身引用、循环、深度超过 8、缺失/篡改快照、当前子工程缺失、revision 漂移、越界或无法证明的时长全部失败关闭。

### 2.2 精确时间映射与编辑

- 父工程以整数帧为权威，子区间以约分整数有理数为权威；交叉验证使用 BigInt，浮点秒不进入业务身份。
- 24、25、24000/1001、30000/1001 以及重复 split/trim 的 source offset/step 都有回归门禁；move/ripple/undo/redo/CAS 沿用既有原子编辑链。
- 动态 `framemd5` 探针曾发现旧 FFmpeg PTS 让 30→24 首帧从 F1 开始。本轮改为按子 timebase 重建离散帧时钟，再按父 fps 采样，并把缓存语义升级为 `mapped.frames-v2`；双向分数帧率逐父帧结果已对照通过。

### 2.3 统一递归 resolver

- 子工程先递归合成画面、画中画、字幕和音频，再应用父片段的源区间、变换、滤镜、opacity 和音量。
- 同步/后台成片、合成帧、Continuation、Publication 和 Electron 预览共享 `aicanvas.nested-timeline.ffmpeg.v1`、依赖 manifest、内容寻址 render plan 与递归 source refs。
- 业务缓存使用 FFV1+PCM；Electron 另从同一无损缓存派生 H.264/AAC faststart MP4，避免把 Chromium 不保证支持的 MKV 当作可见验收。
- timeline 片段的音频只混入一次；三层真实媒体对照证明父音量衰减生效，没有重复播放子音频。

### 2.4 OTIO、MCP 与命令审计

- OTIO export/import 接受 `aicanvas.nested-timeline.v1` 约束的 `Stack.1` 私有子集；导入从冻结快照重建 canonical children，并与标准字段、私有双哈希、RationalTime、transform/filter/opacity/keyframes 交叉校验。
- 未知 Stack/Timeline、Effect、Transition、marker、缺字段、非法 rate 和攻击者重算自哈希的篡改都在创建工程前拒绝，不留下空工程或 render plan。
- MCP 继续使用 `apply_edit_operation` 与 `execute_command`；源码和 `dist-mcp` 都验证新增、幂等重放、陈旧父 CAS、子漂移和显式刷新。
- 明确未提交的 revision CAS 冲突现在由 `RejectedCommandFailure` 记为账本 `failed`、事件 `committed:false`；其他确实无法确认副作用的异常仍保守保持 `unknown`。
