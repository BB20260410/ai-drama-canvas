## 4. 真实物理拖出门：未通过

结构化证据：`docs/evidence/native-media-drag-physical-gate-20260728-v1.json`

实际做到：

- 最终物理尝试使用安装版画布，图片 / 视频 / 音频节点和拖出手柄均正常。
- Main `startDrag` 已执行，应用私有复制体已准备并进入保留期。
- Finder 目标窗口获得焦点，但目标目录仍为 0 文件；TextEdit / Preview 未收到内容。

阻塞原因：

- 当前 Computer Use 的 `sky.drag` 只有起点和终点，没有“按住、分段移动、目标停留、明确松键”的时序控制。
- Electron `startDrag` 会进入同步原生拖拽循环；当前合成输入在 Main 接管前已经释放，表现为 Finder 获焦但没有文件。
- 产品实现符合 Electron 官方 `dragstart → preventDefault → ipcRenderer.send → webContents.startDrag({ file, icon })` 合同。
- 不为迎合自动化改成 `pointerdown` 或暴露临时路径；那会让普通点击误触发系统拖拽并削弱安全边界。

因此，本轮只能判定为：**自动化物理门 BLOCKED，不是产品 PASS，也没有足够证据判定产品 FAIL。**

最终需要一次真人鼠标验收：

1. 从安装版画布分别把图片、视频、音频拖到 Finder 新文件夹。
2. 再把图片拖到 TextEdit、Preview 或另一款支持图片拖入的软件。
3. 核对落点文件 SHA / 大小与源一致、inode 不同。
4. 返回画布确认三个节点仍存在，CAS 原件仍可读取。
