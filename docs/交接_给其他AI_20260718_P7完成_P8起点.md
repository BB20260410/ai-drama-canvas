## 二、用户最核心的产品需求

用户不是只要一个“能摆节点的画布”，也不是只要一套生图提示词。最终要的是一个**本地、隔离、可扩展、可由 Codex/MCP 连接操作的 AI 短剧素材知识中心与无限画布**。

必须满足以下核心目标：

### 1. 能长期保存大量 AI 短剧素材而不卡顿

- 保存剧本、小说、章节、提示词及其不可变版本。
- 保存角色、场景、道具的图片、结构化信息、别名、身份特征、正向硬锁、禁项、适用范围和权威版本。
- 保存生成后的图片、视频、音频，以及图片缩略图、视频代理/封面、音频波形。
- 大媒体本体进入工程内 CAS，不嵌入 JSON 或画布节点。
- 启动只读取当前工程轻量清单与分页索引，不重新扫描或哈希旧工程。
- 列表和画布必须分页、虚拟化、按视口懒加载；不能一次渲染几千宫格或加载原视频/原音频。

### 2. 用户能在无限画布上直观看懂项目

- 能看到季、集、15 秒单元、2–6 宫格、剧情、时间段和提示词。
- 能看到每个角色、场景、道具的权威图、信息、版本、硬锁、Review 和出场时间线。
- 点击资产能分页看到它在哪一集、哪一单元、哪一宫格出现，并直接跳转。
- 能看到歧义、缺失、过期、连续性冲突和返工队列。
- 能看到当前唯一下一动作，以及为什么被阻断；该动作必须由 Core 推导，不能由 UI 猜测。

### 3. Codex 后续生图前必须自动检索并冻结一致性输入

目标链路是：

```text
剧本/小说
→ 实体提及
→ 搜索已有角色、场景、道具
→ 返回候选、版本和依据
→ 人工确认、消歧或排除
→ 冻结 AssetBindingSet
→ 读取逐格连续性状态
→ 冻结身份参考、连续性参考、提示词与禁项
→ Codex imagegen 单张生图
→ raw/labeled、提示词、参考 SHA、Review 回存画布
→ 后续画面继续引用当前已验收资产与上一格 raw
```

必须保证：

- 使用同一个规范资产 ID、当前 Authority 版本、媒体 SHA 和硬锁规则；
- 已知资产不能静默退化成 text-only；
- 歧义不能静默选第一个候选；
- 未验收、过期、漂移或悬空资产不能进入正式生成；
- 剧本、资产、Review 或连续性变化后，下游证据自动过期；
- 同一输入与裁决产生稳定的 BindingSet、引用闭包、生成 pack 和指纹；
- 结果仍必须经过可追溯人工视觉验收。

软件不能诚实承诺“像素级绝对同脸、同犬纹、同构图、同光线”。软件真正能保证的是身份、版本、引用、SHA、提示词、禁项、幂等、门禁和证据闭包；画面是否真的一致，由人工或视觉模型 attestation 裁决。

### 4. 15 秒宫格故事图是正式产品能力

- 每个 15 秒单元根据剧情使用 2–6 宫格，不能少于 2、不能超过 6。
- 一张中文宫格故事板应显示每格画面、动作、景别/构图、拍摄方式、连续性/声音、台词/字幕和时长，合计严格为 15 秒。
- AI 画面本身每张单独生成；不能让模型把多格、表格、字幕、水印或乱码直接画入正式 raw。
- 宫格板由本地排版器把已验收单图与中文信息组合生成。

### 5. 后续正式生成只使用 Codex imagegen

- 用户已经明确：今后生图只由 Codex 调用自身 imagegen。
- 不再建设 Artlist、侧边浏览器、Chrome、网页供应商或“一图一子代理”作为正式供应链。
- P8–P10 软件研发期间继续不生正式图；只有功能验收不可替代时使用 `/tmp` 确定性 fixture。
