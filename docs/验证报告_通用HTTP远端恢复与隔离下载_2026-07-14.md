## 1. 优先级核验

基线源码将 `waiting_remote` 期间的 5xx、断连、坏 JSON、结果 URL 缺失、下载中断和供应商明确失败都经由普通 throw 闭合为本地 `failed`；下载又直接写预留最终路径，崩溃 partial 可被误当完成文件。这会错误关闭仍在运行或已产生结果的付费任务，并诱发重复提交，因此原交接 P0 仍成立。本轮没有重复建设已验证的 Publication、媒体运行时或剪辑关键帧。

## 2. 完成的纵向切片

- 远端观测结构化为 `pending / succeeded / confirmed_failed / retryable_or_unknown`，阶段覆盖 submit、poll、download、validation 和 publish。
- 一旦持久化 `externalTaskId` 或结果地址，暂态观测保留 `waiting_remote`、`clientJobId`、提交意图与 Publication `reserved`，同一任务绝不重新 POST。
- `processGenerationQueue(root, { jobId })` 与 MCP `process_generation_queue(jobId)` 可定向恢复一个已有任务，不顺带提交其他 queued 任务。
- HTTP 结果先写 `.aicanvas/generation-downloads/<job>/result.partial`，刷盘后以不可覆盖链接转为 `result.ready`；发布前执行大小上限、魔数、Sharp/ffmpeg 完整解码和 SHA-256。
- 最终路径异内容转为 `inspect_publication` 人工解决，不覆盖、不死循环重试；图片 labeled companion 同样使用完整解码、尺寸/SHA 一致和 no-clobber 发布。
- 取消只在 HTTP 204，或 HTTP 200 且结构化状态为 `cancelled/canceled` 时关闭本地任务；200 pending、503 或断连都保留任务与 Publication。
- 取消前先对账 Publication：已登记回执优先恢复成功，不向远端发送迟到的取消；已 failed/cancelled 优先投影项目终态。
- Doctor、统一快照、MCP 任务/资源、命令回放/账本/对账和 changes resource 不返回提示词、完整签名 URL 或凭据。
- 新 provider 配置拒绝 endpoint/poll/cancel/site URL 中的敏感 query/fragment；MCP 读取旧工程时再次脱敏 provider URL。

## 5. 下一唯一最高优先级

P0 改为“HTTP `submission_unknown` 结构化对账回写 API”。当前已确保提交断连后不会重新 POST，但没有一个合法、幂等、带修订的写入出口去表达“已按 clientJobId 找到同一远端任务”或“已有足够证据确认未提交”。因此任务、Publication 和同节点新建会永久锁住，只能通过非法手改侧车解除。这是长期章程的“不可恢复”和重复付费防护 P0，高于 `comfyui-local` 专用适配、复杂嵌套和第三方 Effect/Transition 兼容。

下一切片必须在既有 GenerationJob/Publication/命令账本内实现 `found` 与 `not_found` 结构化对账，要求 `expectedRevision + requestId + idempotencyKey`；`found` 只转入同任务 `waiting_remote`，`not_found` 明确关闭旧 Job/Publication 后才允许新版本，两者都不得发起 POST。并发 Publication 终态必须优先，Doctor/快照/MCP 需提供可执行动作，loopback 需证明单次 POST、重启恢复、过期修订/冲突幂等、源码态/编译态 MCP 脱敏与无残留。
