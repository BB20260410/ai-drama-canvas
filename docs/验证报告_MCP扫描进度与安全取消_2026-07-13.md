## 结论

本轮补齐了桌面取消能力与 Codex/stdin MCP 之间的真实断层：

- `scan_project`、`execute_command(command=scan_project)` 和 `preview_scan_project` 现在接收 MCP 请求的 AbortSignal；
- stdio 客户端提供 `onprogress` 时会收到严格递增的 `notifications/progress`，消息包含阶段、候选数、新检数和复用数；
- 取消会传到扫描器及正在运行的 ffprobe，且只在索引提交点前生效；
- 提交点前取消保留上一份 `index.json`、SQLite、`project.scanned` 事件与 `scanId`；
- 命令账本新增明确终态 `cancelled`，同时追加 `command.cancelled`，不伪造 `command.side-effect-committed`；
- 已取消的 requestId/idempotencyKey 不能自动重放，重新扫描必须使用新键；
- 请求登记前已经取消不会写账本；第二个同键等待者取消只停止自身等待，不会误杀原执行者；
- 可能涉及付费或远端副作用的其他写命令不会因为 MCP 客户端断线被盲目中止；
- `get_capabilities` 协议版本升级为 `1.1`，并结构化公开取消边界与账本语义。
