## 允许的操作（四 + 二）

### 基础四项（src/core/ 非 owner 文件 + src/renderer/）

| 操作 | 含义 | 示例 |
|------|------|------|
| **清理 (Clean Up)** | 删除无用 import、注释掉的废代码、临时 hack | 删除 `// TODO: remove after P5` 类注释及其对应死代码 |
| **梳理 (Sort Out)** | 补文件头注释、理清函数调用链、标注复杂逻辑段落 | 给 `editor.ts` 中 De Casteljau 分段逻辑加段落注释 |
| **加固 (Harden)** | 在 IPC 边界、JSON.parse、用户输入处加防御校验 | `try/catch` 包裹 `JSON.parse`，失败返回空态而非崩溃 |
| **规范化 (Normalize)** | 统一命名风格、错误处理模式、日志格式 | 所有 `console.error` 统一为 `[模块名] 描述` 格式 |

### 追加两项（仅限 src/renderer/src/components/*.vue 内部）

| 操作 | 含义 | 约束 |
|------|------|------|
| **精简 (Simplify)** | 砍掉组件内冗余逻辑、重复判断、过度嵌套 | 不改 props/emits/defineExpose 接口 |
| **封装 (Encapsulate)** | 把组件内重复 UI 模式提取为 composable 或子组件 | 新文件放 `src/renderer/src/composables/` |

### 行为变更判定规则（解决"加固"与"不改行为"的矛盾）

**允许的行为微调**：
- 添加 try/catch 防御（catch 中**必须** console.error + 返回空态/默认值，**禁止静默吞错**）
- 添加参数校验（校验失败抛 TypeError 或返回 undefined）
- 添加 `// REVIEW` 注释

**禁止的行为变更**：
- 改变函数返回值类型/结构
- 改变事件触发顺序或异步操作时序
- 删除任何现有分支逻辑（即使看起来是死代码）
- 改变 props/emits 的类型或名称

**无法判定时**：加 `// REVIEW: 待确认` 并跳过，不要猜。

## 参考范例：什么叫“好的精简”

以下是本项目 `ManagedStudioCanvasView.vue` 中的真实代码（第 1841–1896 行）：

**改前（重复 3 次的分页游标逻辑，~56 行）：**
```typescript
// 单元分页
async function unitsNext(): Promise<void> {
  const next = unitsPage.value?.page.nextCursor;
  if (!next) return;
  unitCursorStack.value.push(unitCursor.value ?? "");
  unitCursor.value = next;
  await guarded(loadUnits);
}
async function unitsPrevious(): Promise<void> {
  const previous = unitCursorStack.value.pop();
  if (previous === undefined) return;
  unitCursor.value = previous || undefined;
  await guarded(loadUnits);
}
// 资产分页——逻辑完全相同，只是变量名不同
async function assetsNext(): Promise<void> { /* 同上 */ }
async function assetsPrevious(): Promise<void> { /* 同上 */ }
// 出场分页—— again
async function appearancesNext(): Promise<void> { /* 同上 */ }
async function appearancesPrevious(): Promise<void> { /* 同上 */ }
```

**改后（提取 composable，原组件只剩 3 行调用）：**

新文件 `src/renderer/src/composables/use-cursor-pagination.ts`：
```typescript
/**
 * 游标分页复用逻辑：维护 cursor + stack，提供 next/previous 操作。
 * 被 ManagedStudioCanvasView 的 units/assets/appearances 三处分页复用。
 */
import { ref, type Ref } from "vue";

export function useCursorPagination(
  getNextCursor: () => string | undefined,
  reload: () => Promise<void>,
) {
  const cursor: Ref<string | undefined> = ref(undefined);
  const stack: Ref<string[]> = ref([]);

  async function next(): Promise<void> {
    const c = getNextCursor();
    if (!c) return;
    stack.value.push(cursor.value ?? "");
    cursor.value = c;
    await reload();
  }

  async function previous(): Promise<void> {
    const prev = stack.value.pop();
    if (prev === undefined) return;
    cursor.value = prev || undefined;
    await reload();
  }

  function reset(): void {
    cursor.value = undefined;
    stack.value = [];
  }

  return { cursor, next, previous, reset };
}
```

原组件中变为：
```typescript
const unitsPager = useCursorPagination(
  () => unitsPage.value?.page.nextCursor,
  () => guarded(loadUnits),
);
const assetsPager = useCursorPagination(
  () => assetsPage.value?.page.nextCursor,
  () => guarded(loadAssets),
);
const appearancesPager = useCursorPagination(
  () => appearancesPage.value?.page.nextCursor,
  () => guarded(() => loadAppearances(currentAssetId)),
);
```

**为什么这是好的精简：**
- 56 行 → 3×4 行调用 + 1 个 35 行 composable（净减 ~10 行，但消除了 3 倍重复）
- composable 可被单测（原来内联在 SFC 中无法测试）
- 不改任何 props/emits，不改 template 事件绑定（只把 `@click="unitsNext"` 改为 `@click="unitsPager.next"`）
- 行为完全等价
