# Writing OS 桌面仪表盘与状态候选 Diff P0 验收报告

## 交付结论

已完成。Novel Studio 现在把“正文保存”与“章末状态提交”明确分开：用户可以在桌面端看到下一章 readiness、当前章状态债和一致性探针，检查待裁决候选的八项 before/after Diff，并通过受限的 `human_ui` 接受或拒绝。接受后仪表盘会自动刷新到状态已提交、探针通过、候选归零。

## 实际交付

- 新增经过净化的桌面 Writing OS 聚合 DTO；不向 renderer 暴露项目根路径、原始 source object、token 或 `author_only` 正典内容。
- 新增待裁决候选的有界、安全发现，并校验候选、裁决和工程身份。
- 新增两条严格 typed IPC：读取仪表盘、人工裁决候选。
- Main 固定注入 `desktop-human-owner` 与 `human_ui`；renderer 不能伪造 reviewer 或 owner actor。
- Novel Studio 右栏新增“总控 / 候选 / 记忆”：展示 readiness、状态版本、状态债、机器冲突、下一步、八项 Diff、证据和接受/拒绝。
- 正文保存、章节切换和候选裁决后自动重读仪表盘；使用请求序列阻止旧异步响应覆盖新章节状态。
- 将最终章无下一目标显示为正常终态，不再冒充阻断。
- 一致性探针只消费 writer-visible hard canon，避免 `author_only` 侧信道。
