# Writing OS P1 性能加固验收报告

日期：2026-08-02

## 最终裁决

`VERIFIED`

旧版 500 章验收暴露的线性尾延迟已经关闭。在同一套 1,014,334 字符、500 章顺序写入、从第 200 章重建到第 500 章的隔离夹具上：

- 正常写章 p95 从 `12,732.71 ms` 降到 `2,196.55 ms`，下降 `82.75%`。
- 正常写章 mean 从 `7,621.12 ms` 降到 `2,080.22 ms`，下降 `72.70%`。
- 旧章重建 p95 从 `3,167.74 ms` 降到 `995.18 ms`，下降 `68.58%`。
- 峰值 RSS 从 `615,858,176` 降到 `556,990,464` bytes，下降 `9.56%`。
- 第 1–50 章与第 451–500 章的正常写章 mean 仅相差 `+0.74%`，末窗口 p95 反而下降 `6.53%`；没有再随 operation history 形成线性雪崩。

因此，上一轮 `VERIFIED_WITH_PERFORMANCE_RISK` 中指向 `12.73s p95 + O(n²) operation 扫描` 的 P1 风险，在本次受测范围内已关闭。`VERIFIED` 只适用于 Writing OS 的机械一致性、可恢复性和本次百万字符规模性能，不代表自动保证文学质量或所有未来硬件与并发负载。

## 实际改动

1. 为 Writing State 与正文 mutation 的 append-only operation 增加 durability-backed pending journal。旧 operation locator 与历史工件保持不变；热恢复只枚举未完成 marker，显式 full verification 仍审计全部旧 archive。
2. layout 不存在的旧工程先完成一次 legacy 全量恢复/校验，再发布 `pending-markers-v1` 布局；新旧工程可混合读取，不靠进程内缓存猜测状态。
3. 增加同目录不可变文件批量持久化：每个文件仍独立写入并 fsync，非提交工件先 rename，目录 fsync 后把 `intent.json` 最后发布，再做最终目录 fsync。
4. state operation 和 manuscript intent bundle 使用批量原语，保留 intent 提交点、inode/SHA CAS、第三状态拒绝、旧 locator 和既有故障注入语义。
5. 500 章脚本增加 prepare/save/stage/accept 分阶段计时和窗口延迟，能机械区分固定成本与随历史增长的尾延迟。

本轮没有为追求速度关闭 fsync、降低 CAS、跳过 full-lineage verification，也没有改写 checkpoint schema。最终 Writing State 为 `915,062` bytes；它没有造成后 50 章延迟失控，因此不引入风险更高的 delta checkpoint。
