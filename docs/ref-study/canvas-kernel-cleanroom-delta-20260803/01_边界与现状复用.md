# 边界与现状复用

## 执行裁决

Grok 的方向“Canvas 做内核、外部工具只作可选研究”成立，但原任务书不能原样执行。经源码与合同去重后，本轮只执行 clean-room 差异研究；下列动作明确不做：

- 不执行 `npm install @actalk/inkos`，不下载或启动未签名 DMG；
- 不执行 NovWr 的 `curl | bash`、Docker pull/up 或任何会初始化用户目录的脚本；
- 不 clone、链接、翻译或移植 GPL/AGPL 实现；
- 不把外部软件连接到正式《黑页》工程、正式项目数据库或模型密钥；
- 不新建 `author_intent`、`current_focus`、人物状态或正典的第二份权威存储；
- 不改 `src/`、`package.json`、lockfile，不执行 Git 暂存、提交、推送或 PR。

## 为什么不执行“三套必装”

“把安装包放进一个目录”不等于隔离运行：

| 外部项目 | 官方行为/前提 | 对原方案的影响 |
|---|---|---|
| InkOS | npm 包为 AGPL-3.0-only；未固定版本安装还会使用 npm 全局缓存/解析链 | 没有需要运行验证的独立产品假设，安装只增加许可与供应链面 |
| AI-Novel-Writer | 官方说明 macOS 安装物未签名/未公证，配置和数据写入 `~/.vela` | 仅把 DMG 放在 sandbox 目录不能约束其写入边界 |
| NovWr | 官方安装脚本会安装 uv/CLI、初始化 `~/.novwr` 并依赖 Docker | `curl | bash` 与 Docker 启动明显超出只读研究；本机 Docker daemon 也未运行 |
| OCNovel | Grok 未给 owner/repository/commit | 不能在身份不确定时安装；当前只能记录 probable match |

因此，本轮通过 GitHub API、npm registry 与固定 commit 的 README 身份做只读研究，外部制品下载数和外部可执行程序运行数均保持为零。

|---|---|---|

## Clean-room 规则

1. 只记录公开行为、信息架构、输入输出和验收目标，不记录或改写外部代码结构。
2. 外部许可证、commit、release、package integrity 必须可复现；身份不完整时标记不确定，禁止自行补成确定事实。
3. Canvas 的 Context Pack、preflight、fingerprint、CAS、状态候选和人工结算继续是唯一写章协议。
4. 外部草稿一律是不可信候选，不能绕过 Canvas 的 stale 检查、CAS、状态候选或人工接受。
5. 此研究不构成兼容性承诺、性能证明或百万字一致性保证。
