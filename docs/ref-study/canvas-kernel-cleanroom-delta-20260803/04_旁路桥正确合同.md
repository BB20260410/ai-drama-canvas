# 外部执行器旁路桥合同

## 核心结论

任何外部 AI/小说软件若要参与写章，顺序必须是 **Canvas 先 prepare，外部执行器后写草稿**。Grok 原草案中的“外部先写、之后再 prepare”不能证明草稿使用了受管 Context Pack，也不能获得 preflight-bound save 身份。

## 正确顺序

```mermaid
flowchart LR
    A["Canvas doctor"] --> B["prepare: pack + preflight + fingerprint"]
    B --> C["导出只读 work order"]
    C --> D["隔离外部执行器生成草稿"]
    D --> E["以 untrusted candidate 回传"]
    E --> F["按原 fingerprint 做 stale + CAS save"]
    F --> G["stage state candidate"]
    G --> H["人工 accept / reject"]
    H --> I["consistency probe + 下一章 readiness"]
```

## Work order 最小字段

导出的 work order 应是一次性的、只读的，并至少固定：

- project/novel/chapter 的稳定身份；
- base revision 与预期 CAS revision；
- `cutoffChapterId`；
- Context Pack fingerprint；
- preflight fingerprint/receipt；
- chapter brief、required cast、允许的 canon/state 片段；
- included/omitted receipt 与预算；
- 输出格式、禁止事项与有效期；
- 不包含模型密钥、本机绝对路径、future chapter 或 author-only 内容。

## 回传候选最小字段

- 原 work order ID、pack fingerprint、preflight fingerprint；
- 外部执行器身份与版本（若可取得）；
- 草稿内容 hash、生成时间和声明的输入 hash；
- 不可信正文候选，不带“已保存”“已结算”或“已通过文学审查”结论。

## Canvas 必须重新验证

1. project/chapter/base revision 仍匹配；
2. pack/preflight fingerprint 未 stale；
3. cutoff 未越界，work order 未过期；
4. CAS save 成功后才可称正文进入受管稿；
5. 状态变化先进入 candidate，必须人工 accept/reject；
6. probe 只证明机械合同，不冒充文学质量验收。

## 明确拒绝

- 外部工具直接写 Canvas 数据库、manifest、章节 Markdown 或状态文件；
- 外部草稿先生成，再补建 pack/preflight 以伪造绑定；
- fingerprint 不一致时自动重打包并静默保存旧草稿；
- 自动接受人物状态、关系、知情、伏笔或日历变化；
- 将外部工具自己的 project/character/world model 设为第二权威；
- 正式小说源与测试工程双写。

## 本轮执行边界

本轮只落盘上述合同，没有实现桥接代码、没有创建 runtime sandbox、没有向任何外部 App 导出作业包，也没有生成或保存正式章节。
