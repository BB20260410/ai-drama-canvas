# 小说软件源码与架构审计索引

## 最终结论

`ARCHITECTURE_WORTH_LEARNING_CODE_NOT_FOR_DIRECT_INTEGRATION`

这些软件对 Canvas 有用，但用处是“提供可验证的设计模式”，不是“换掉当前 Writing OS”，也不是“把外仓代码合并进来”。

源码审计后的精确裁决：

1. Canvas 在 cutoff 时态投影、Context Pack fingerprint、正文 CAS、角色必备集、证据绑定状态候选、人工 accept/reject 和状态重建上，已强于本轮所有外部项目的组合。
2. 外仓真正能补的是工程差额：派生索引代际、长任务过期对账、pack 选择轨迹，以及低优先级的知识来源/叙事承诺诊断。
3. GPL/AGPL 项目的代码不进 Canvas；MIT 项目虽许可宽松，但其架构与 Canvas 的 file-first owner 不匹配，也没有直接复制的必要。
4. 安装这些软件不能自动保证 100 万字一致性；有用的是在 Canvas 唯一 owner 内 clean-room 重建其中的好协议，然后做长压测、崩溃恢复与真实小说召回率验收。
