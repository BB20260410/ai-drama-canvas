## 高并发中发现并修复的真实缺陷

1. 排队轮询定时器错误使用 `unref`，纯 CLI worker 可能在等待容量时提前退出。现已让容量等待保持事件循环。
2. 极快 ffprobe 可能在租约绑定落盘前退出；旧顺序尚未安装 `close` 监听，会永久占住容量。全量现场曾明确出现 4 个死亡 childPid 对应的活跃租约和持续排队。现改为生成子进程后、任何 `await` 之前安装监听，并新增 20 个毫秒级子进程回归门禁。
3. 临时安装结构中的 MCP 已解包，但依赖仍只在 `app.asar`，独立 Electron-as-Node 会报 `ERR_MODULE_NOT_FOUND`。现将生产运行依赖一并解包，安装结构不再借用开发工作区依赖。

## 运行合同与已知边界

- 默认运行时目录为 `~/.aicanvas/runtime/media-v1`，可用 `AI_CANVAS_MEDIA_RUNTIME_DIR` 隔离测试；容量可用 `AI_CANVAS_MEDIA_CAPACITY` 调整。
- 严格 FIFO 会让能塞进剩余容量的小任务等待队首重任务，代价是避免重任务永久饥饿；渲染权重 3 会刻意保留 1 个 ffprobe 槽位。
- 运行时是可重建的机器协调状态，不是项目业务事实源；损坏时失败关闭，不静默重置。
- 孤儿回收在下一次受控媒体获取或 `list_edit_render_jobs` 恢复时触发；Doctor 只读报告死亡宿主，不后台修改状态。
- macOS 已验证 POSIX 进程组终止；Windows 仍使用单 PID 回退，未在本轮验证。
- 发布注册仍在 `publications` 锁内执行 ffprobe 和 SHA-256；这是下一唯一 P0，不属于本切片。
