P2：
性能、可观测性、桌面交互、批量效率、大项目能力和错误修复体验。

P3：
兼容性、导入导出完善、分发、公证、文档和非阻断优化。

P4：

12. MCP 返回结构化摘要、路径和状态，不返回 base64、巨型图片 JSON 或无边界日志。
13. 视觉质量、表演、构图、角色一致性和最终轴线不能由机械测试代替，必须明确进入人工视觉验收。

七、小说到15秒分镜的稳定合同

→ 15秒单元
→ 单元内镜头
→ 硬规则校验
→ 连续性警告
→ 提示词与画布节点

必须保持：

- 原文文件、章节、字符区间和内容哈希可追溯；
- 原文事实、模型推断和不确定信息明确区分；
- 一个15秒单元累计不超过15秒；
- 默认不超过约6镜；
- 单镜时长为正数；
- 镜头顺序和ID稳定且不重复；
- 台词字数与可说时长可配置校验；
- 人物、场景、服装、道具和硬锁引用必须存在；
- 重要事实必须有原文证据或明确标记为推断；
- 相邻镜头保存人物状态、动作、视线、道具、时间、场景和情绪连续性；
- 修改局部前先计算影响范围；
- 不能无故重写其他单元；
- 保存版本、修订和追加式审计；
- 重启后恢复；
- JSON 和 Markdown 导出可验证。

镜头叙事效果、表演自然度、最终构图、视觉轴线和人物面部漂移只能生成结构化警告和人工验收项，不能虚报为程序完全判断。

十一、开源与竞品研究边界

优先读取现有开源审计文档。只有当前具体缺口无法从本仓库、已有文档和现有抽象中解决时，才进行新研究。

每次研究必须回答：

- 当前要解决哪个具体缺口；
- 候选项目的官方源码或论文地址；
- 许可证；
- 最近维护状态；
- 技术栈；
- 可借鉴的数据结构、调度机制、公开算法或交互逻辑；
- 集成成本；
- 商业与许可证风险；
- 是否马上实施，或为什么拒绝。

ToonFlow、小云雀和其他竞品只做 clean-room 功能分析。不得复制许可证不兼容源码、私有接口、品牌、图标和独特界面。

调研本身不是交付。没有明确可落地项时立即停止调研，返回实现。

十二、测试和证据门禁

验证强度与修改风险相匹配。

每个实现切片：

- 先运行相关定向测试；
- 运行相关类型检查；
- 运行真实最小夹具；
- 验证错误路径、取消、重试和恢复；
- 保存简洁证据。

达到里程碑、交接或准备报告广泛完成时，再运行：

1. typecheck；
2. 全量自动测试；
3. MCP smoke；
4. 生产构建；
5. 真实运行态验证；
6. 相关 UI 交互验证；
7. 恢复和重启验证。

只有涉及安装包或发布行为时，才要求重新：

- 构建 DMG；
- 校验签名；
- 运行包内 MCP、UI 和 headless 能力；
- 生成新的安装包哈希。

源码修改后，旧安装包不能证明当前源码已经进入安装包。

证据要求：

- 可见 UI 修改：真实应用截图或交互自动化；
- 媒体功能：真实 FFmpeg/ffprobe 输出；
- 文件闭环：落盘、大小、魔数、尺寸或时长、可解码、哈希和版本关系；
- 恢复能力：关闭进程、跨进程或重启验证；
- 并发能力：真实并发、跨项目或跨进程测试；
- 导出能力：真实文件落盘并重新解析；
- 正式项目能力：必须在用户明确授权后用真实项目校准；
- 网站能力：必须用用户授权的真实网站验证；
- 视觉能力：必须由人工视觉验收。

mock、类型、按钮、测试夹具或机械检查只能证明它们实际覆盖的范围，不能替代真实网站、正式项目、付费结果和视觉质量。

十三、正式项目导入规则

当我提供正式项目绝对路径后，按以下步骤执行：

1. 确认本轮授权范围；
2. 先做只读预检；
3. 列出预计识别的目录、单元、素材、旧版、忽略项和硬锁；
4. 列出预计创建或修改的文件；
5. 确认没有跨越授权根；
6. 再进行确认式导入；
7. 创建或更新 .aicanvas；
8. 机械验收；
9. 抽样视觉检查；
10. 汇报识别错误、未识别命名和需要人工确认的权威版本。

- 总索引和项目配置。

“没有发现新问题”不等于整体完成。

只有重新从长期目标生成完成矩阵，并且关键能力都有直接证据后，才能讨论整体完成。至少包括：

- 无限画布真实编辑与重启恢复；
- Codex 通过 MCP 完成读取、修改、生成、回填和导出；
