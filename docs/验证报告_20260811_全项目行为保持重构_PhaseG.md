# 全项目行为保持重构 · Phase G 验证报告

## 结论

Phase G 已通过，整个重构计划进入 Phase H 最终冻结验收。Immutable MCP candidate 的 stage、
publication/cutover 与隔离 App 终态证据已分层；固定根、source currentness、依赖闭包、
publication fingerprint 与唯一 launcher rename 没有放宽。

## 已完成改动

1. 新建 `immutable-mcp-candidate-stage.ts`，承载隔离 stage 的命令与 payload 编排；
   `computeSourceDigest`、live `dist-mcp` currentness、固定输出根与 CLI 仍在主入口。
2. 新建 `immutable-mcp-candidate-cutover.ts`，把 candidate/publication 联合落盘和唯一 launcher
   rename 保持在同一 publication lock 临界区。
3. launcher 已提交后，lock release、最终联合回读或清理失败均返回 `committed=true` typed
   error；命令保持失败但明确禁止自动重试，不再冒充“未发布”。
4. 隔离 package smoke 改为两阶段 no-clobber 证据：持锁写不可判 PASS 的 terminal，释放并
   验证规范 lock 消失后，再写绑定 runId 和 terminal SHA-256 的 completion marker。
5. publication stale lock 回收增加独占 reaper；持有 reaper 后重新读取、验活、再 rename，
   防止两个回收者移走新 owner 的锁。
6. candidate stage 恢复独立 HOME、空 npm userconfig 和官方 registry，避免用户 `.npmrc`
   影响锁文件重建结果。

## 保持的顺序与边界

实际顺序固定为：`npm ci → launcher bundle → build:mcp → build:identity → currentness →
prune/ls → payload copy → receipt/verify → runtime smoke → publication → launcher rename`。

- runtime smoke 依赖已复制并封存的 candidate tree，因此没有按旧摘要文字移动到 payload copy 前。
- candidate/publication 可在 rename 前成为不可变孤立历史；失败时不删除这些合法审计记录。
- `current.mjs` 仍是有锁保护的唯一可变指针，不套用 evidence 的 append-only 语义。
- terminal 单独存在、runId 为空、terminal hash 不匹配、completion 指向假 lock 或真实 lock
  仍存在时，一律不能判为完成。
