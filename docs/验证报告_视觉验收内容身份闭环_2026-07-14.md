## 2. 根因与内容身份合同

旧状态把三个不同概念混在一起：

1. `artifactId`：稳定逻辑路径身份；
2. 当前文件内容：同路径可变化；
3. Review 状态：曾只引用一个 ReviewRecord。

新合同明确分离：

- ReviewRecord 保存 `rootSlot + relativePath + kind + variant + size + SHA-256` 的不可变 `artifactEvidence`；
- `StatusOverride.reviewEvidenceIds` 分别保留 `image` 与 `video` 相位证据；
- shot 完成必须有当前 raw/labeled 的 image pass；
- unit 进入待视频、视频生成中、待视频验收或视频返工前，当前四张权威首尾帧必须仍由 image pass 覆盖；
- unit 完成还必须叠加当前权威视频的 video pass；
- 图片漂移优先回到“待视觉验收”，视频漂移回到“待视频验收”。

`expectedScanId` 保留为验收快照的来源追踪，不宣称其本身是 CAS token。真正的内容并发门禁是所选素材 SHA-256、首次定点扫描、提交前二次定点扫描，以及 ReviewRecord 落盘后的状态扫描。

## 3. 实现闭环

### 3.1 Scanner 与 Review

- scanner 只强制哈希 override 实际引用的 ReviewRecord 和受限 legacy 相位候选，不再永久哈希全部历史；显式验收路径即使超过 100 MB 也必须计算 SHA。
- 哈希使用固定 `O_NOFOLLOW` FileHandle，并在前后核对 dev/ino/mode/nlink/size/mtimeNs/ctimeNs 与路径身份。
- legacy artifactIds-only 记录继续可读历史，但不能证明当前完成。
- Review queue 使用两遍只读 preview：第一遍得到真实回落队列，第二遍给最终队列媒体补 SHA，消除旧索引无 SHA 时无法重验的死循环。
- 视频 pass 在首次扫描和最终扫描后都重新验证当前四张图片的 image pass。
- 最终扫描后、ReviewRecord 写入前若外部工具换文件，post-record scanner 不推进状态，并返回 confirmed failure；该记录只作为历史保留。

### 3.2 状态、并发与 Production

- generation 的批量状态写入保留 image/video 相位证据，不再清空图片 pass。
- `updateStatus`、`updateStatusOverridesBatch`、`setAuthoritativeArtifact` 对 `overrides.json` 的 read-modify-write 统一使用项目级 `overrides` 锁，消除不同业务域并发 last-writer-wins。
- 视频 rework 从当前证据恢复为视频验收，不再被硬路由到图片。
- Production 的 `video` 与 `review` 阶段自身也校验当前首尾帧 image pass，不再只看视频记录。
- awaiting_review 任务继续绑定本批 artifact SHA；同路径漂移后，即使新内容另行通过，也不能完成旧批次。

### 3.3 MCP 与命令账本

- `get_review_queue` 在最多 20 项的返回窗口中，先放当前权威且必需的媒体，再填历史版本；同时返回 `artifactTotal` 与 `artifactsTruncated`。
- 12 版首尾帧真实 stdio fixture 中，49 个左右的节点素材被截断时，四张 v12 当前权威图及其 SHA 均仍可见。
- 快照漂移、旧哈希或权威冲突发生在写 ReviewRecord 前时，`submit_review` 形成明确 `failed` 账本，不再进入 `unknown`；记录落盘后的异常则按已确认副作用或真正 unknown 处理，禁止危险重放。
- MCP 能力仍为 134 tools、9 Resource Templates、7 Prompts。
