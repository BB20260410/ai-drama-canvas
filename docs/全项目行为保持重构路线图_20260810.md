# 无限画布全项目行为保持重构路线图

> 状态：已完成。Phase A–H 均通过；最终源码、candidate、stdio 与隐藏隔离 App 同身份验收 PASS。

## 1. 结论与边界

本项目不能采用整包重写：现有 Core、SQLite、CAS、命令账本、MCP、Electron 与
Renderer 已包含多组通过验收的 owner。此次“全面重构”固定解释为：

1. 保持数据库、CAS、命令、IPC、MCP、UI 与正式项目行为不变；
2. 逐步消除循环依赖、无界并发、超大入口职责混杂和重复纯函数；
3. 每个切片可独立测试、回滚和停止，不以“大文件变小”冒充收益；
4. 不重建 P0–P14 owner，不建立平行事实源，不迁移正式项目数据；
5. 本轮不执行付费/上传/正式生成、公证、发布或 Git stage/commit/push。

## 3. 防循环执行规则

- 同一时间只有一个写入者；并行代理只做只读审查。
- 每个切片先写明行为不变量与定向测试，再改代码。
- 每个失败最多两轮同范围纠正；仍失败则记录阻塞并停止该切片，不从头重跑。
- 切片阶段不运行 fast/medium/integration/heavy 全量分区，不重复 candidate/package/install。
- 只在源码冻结且全部阶段完成后，才决定是否进行一次最终 candidate、隔离 App 和本机安装。
- 历史 final-validation 与正式项目数据只读；新证据使用新文件名，不覆盖旧证据。

## 5. 明确不做

- 不先拆 legacy/fusion 15 模块 SCC；它跨旧生产、扫描、编辑和生成，首刀回归面最大；
- 不全局合并 43 份 `stableValue`/42 份 `digest`；不同 owner 的 undefined、换行和序列化语义可能不同；
- 不把 IPC/MCP effect 由名称推测；继续保持未知操作默认 strong/mutation 的失败关闭合同；
- 不把脚本编排塞进业务 Core；
- 不把测试改成只检查“文件存在”来掩盖行为变化。

## 6. 当前完成定义

Phase A–H 的各自完成门均已满足，最终等价验证通过，因此本路线图状态为
“全项目行为保持重构完成”。这里的完成严格限于第 1 节定义的行为保持分层范围；
legacy/fusion 15 模块环与日常安装版替换仍按明确边界处理。
