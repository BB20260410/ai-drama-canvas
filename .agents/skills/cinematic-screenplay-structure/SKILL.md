# 电影级剧本结构优化

## 运行时选择

- 用户明确要求诊断或重构短剧的结构
- 从小说/故事/创意梗概改编为结构化剧本
- 检查现有剧本的结构完整性
- 为后续真实时长分镜生产提供上游剧本输入
- 先读取项目的集数、单集时长、平台规则、锁版状态和正典；这些真实约束高于本 Skill 的比例示例
- 三幕式、序列法、Save the Cat、四阶段波浪模型是备选分析框架，按任务选择一个主框架，不能无条件全部套用
- 输入已经锁版或用户只要求诊断时，只输出 `proposed` 结构建议，不直接覆盖正文；正式改稿由剧本 owner 或 `short-drama` 在授权后执行

## 与项目权威链的关系

- 本 Skill 只负责**剧本文案层**的结构优化
- 仅在 `AI 漫剧无限画布` 等明确提供受管 owner 的项目中，优化后的剧本才继续走该项目规定的 `material-studio` → `BindingSet` → 真实时长单元拆镜；其他项目服从其本地生产合同，不强加这条链
- 当前项目存在 `CanonicalAsset`、`BindingSet` 或资产消歧合同时，不发明未绑定资产、不绕过 owner，角色/场景/道具命名与现有权威一致
- 当前项目没有上述受管对象时，只交付剧本结构与 `proposed` 建议，不虚构对应 ID、绑定或机器状态

## 一、Syd Field 三幕式结构（基础骨架）

| 幕 | 占比 | 功能 | 关键节点 |
|----|------|------|----------|
| 第一幕：建置 | 25% | 建立人物、世界、核心矛盾 | 激励事件（Inciting Incident）→ 第一转折点（Plot Point 1） |
| 第二幕：对抗 | 50% | 升级冲突、试炼、中点反转 | 中点（Midpoint）→ 第二转折点（Plot Point 2） |
| 第三幕：解决 | 25% | 高潮对决、情感升华、收束 | 高潮（Climax）→ 尾声（Resolution） |

### 短剧适配

```
第一幕（约前 25%）：钩子 + 人物/矛盾快速建置
第二幕（约中间 50%）：冲突升级 + 中点反转
第三幕（约后 25%）：高潮/悬念爆发 + 收束或下集钩子
```

比例只用于诊断，不是硬切点。真实时长、平台节奏、源稿事件密度或项目合同不适合时，记录偏离原因并采用项目节拍。

## 二、序列法（Sequence Approach）

完整长片常拆为 8 个序列；短剧只借用其功能顺序，按项目总集数与时长合并，不要求凑满 8 段：

| 序列 | 对应幕 | 核心任务 | 情绪走向 |
|------|--------|----------|----------|
| Seq 1 | 第一幕前半 | 日常世界 + 激励事件 | 平稳→打破 |
| Seq 2 | 第一幕后半 | 犹豫/拒绝→跨越门槛 | 抗拒→接受 |
| Seq 3 | 第二幕A前半 | 新世界探索 + 初步胜利 | 好奇→小胜 |
| Seq 4 | 第二幕A后半 | 升级挑战 + 中点反转 | 紧张→震撼 |
| Seq 5 | 第二幕B前半 | 后果扩大 + 盟友/敌人 | 压力→抉择 |
| Seq 6 | 第二幕B后半 | 至暗时刻 + 一切丧失 | 绝望→触底 |
| Seq 7 | 第三幕前半 | 觉醒/新方案 + 集结 | 希望→冲刺 |
| Seq 8 | 第三幕后半 | 终极对决 + 新平衡 | 高潮→余韵 |

### 短剧四阶段波浪模型

按项目总集数或总时长映射，不预设 80 集：

| 阶段 | 参考范围 | 结构任务 | 波峰要求 |
|------|----------|----------|----------|
| 起势 | 前 10%–15% | 高信息钩子、主角困境、核心欲望与主要对手入场 | 尽快形成第一次不可逆选择 |
| 攀升 | 约 15%–45% | 连续兑现类型承诺，小胜与代价交替上升 | 每个波峰都改变关系、资源或认知 |
| 风暴 | 约 45%–80% | 中点反转、优势反噬、真相升级、至暗时刻 | 后一轮冲突必须比前一轮更难恢复 |
| 决战 | 约 80%–100% | 新方案、终局对抗、主题证明与余波 | 高潮解决核心矛盾，尾钩只服务续篇需求 |

阶段边界可随源稿和平台合同移动。不要把百分比换算成固定集号后当成正典。

## 四、人物弧光设计

### 弧光三要素

```
外在目标（Want）：角色以为自己要什么
内在需求（Need）：角色真正缺什么
致命缺陷（Flaw）：阻止角色获得 Need 的性格弱点
```

### 弧光变化曲线

| 阶段 | 角色状态 | 驱动力 |
|------|----------|--------|
| 开局 | 被 Flaw 支配，追求 Want | 恐惧/惯性 |
| 中点 | 开始质疑 Want，隐约触碰 Need | 事件冲击 |
| 至暗 | Flaw 导致最大失败 | 自我否定 |
| 高潮 | 放弃 Want，拥抱 Need，克服 Flaw | 顿悟/牺牲 |
| 结局 | 新平衡，内外统一 | 成长完成 |

### 短剧角色速建模板

```yaml
角色名: 
外在目标(Want): 
内在需求(Need): 
致命缺陷(Flaw): 
口头禅/语言习惯: 
标志性动作: 
视觉锚点(服装/道具/发型): 
人物弧光一句话: "从___到___"
```

## 五、对白结构检查

### 电影级对白五原则

1. **潜台词**：角色说的 ≠ 角色想的（禁止直白陈述情感）
2. **动作性**：检查台词是否推动剧情或揭示人物；锁版源稿中的疑似无功能台词只提修改建议，不直接删除
3. **个性化**：遮住角色名也能分辨是谁在说话
4. **可演性**：按项目语速样本、停顿、表演动作和真实镜头时长测算，不使用固定“每句 15 字”或“3 句一回合”
5. **冲突性**：对话即博弈，每轮对话都有攻守转换

### 对白格式（本项目适配）

```
【角色名】（表情/动作指示）
"台词内容。"
（旁白/内心OS标注）
```

### 旁白使用规则

| 类型 | 适用 | 禁忌 |
|------|------|------|
| 第一人称旁白 | 悬疑揭示、时间跳跃 | 代替画面叙事（能用画面就不用旁白） |
| 第三人称全知 | 史诗感、命运感 | 解释角色心理（应通过表演呈现） |
| 无旁白 | 动作戏、对话戏 | — |

## 六、剧本优化检查清单

对任何输入剧本，按以下顺序检查并输出修改建议：

- [ ] **结构完整**：三幕比例是否合理？转折点位置是否正确？
- [ ] **激励事件**：前 10% 是否有打破日常的事件？
- [ ] **中点反转**：50% 处是否有认知颠覆？
- [ ] **至暗时刻**：75% 处主角是否跌入谷底？
- [ ] **人物弧光**：主角 Want/Need/Flaw 是否清晰？是否有变化？
- [ ] **对白质量**：是否有潜台词？是否个性化？是否有无功能台词？
- [ ] **视觉化**：是否所有情感都通过可拍动作表达？（禁止"他感到悲伤"）
- [ ] **节奏曲线**：是否符合项目约定的节拍密度？每个波峰是否造成可验证的局势变化？
- [ ] **钩子设计**：每集结尾是否有强力悬念/反转/情感锚点？
- [ ] **主题统一**：Opening Image 与 Final Image 是否形成对照？

## 八、明确不做

- 不生成正式 imagegen 提示词（那是 `ai-drama-production-prompts` 的职责）

- 不把社区 Seedance 语法写进软件 Core
- 不覆盖既有 final-validation 或权威交接
- 不替代人工创意判断——本 Skill 提供结构框架，最终创作决策归用户
