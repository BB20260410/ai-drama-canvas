# P3.5 跨集资产复用合同（设计稿）

范围：跨工程（project）复用 Material Studio 规范资产。仓库只读调研，未改动任何文件。

**边界重述（三代理互评已定，不可协商）**：导出=只读 content-addressed 快照；导入=目标项目自己的 **pending 候选**，必须过目标项目 Review/Primary gate，源项目"已过审"只是提速提示，不可跳闸；禁止活体克隆/共享表/跨项目直读源 SQLite——事实源永远是当前项目。

## 1. 导出包结构与 manifest schema

```
<packageRoot>/                              只读，写完即冻结只读位（做法同
  manifest.json                             immutable-mcp-runtime-candidate.ts:307-330 sealImmutableMcpRuntimeCandidate）
  objects/sha256/<前2位>/<sha256全串>        分片布局同 confined-project-storage.ts:327-330
```

manifest.json（`schemaVersion:1, kind:"cross-episode-asset-export-manifest"`）：

```ts
{
  exportId: string,          // "export-<sha16>-<sha16>-<sha8>"，拼接规则同 candidateId()（immutable-mcp-runtime-candidate.ts:184-194）
  exportedAt: string,
  sourceProjectId: string,
  sourceManifestFingerprint: string,     // 源工程 Material Studio 内容摘要
  items: [{
    assetId, assetCategory, versionId, versionOrdinal, mediaSha256,
    reviewStatus, isPrimaryAtExport: boolean,
    sourceReviewId?, sourceAuthorityEventId?,     // 对应 studio_version_reviews.id / studio_authority_events.id（material-studio.ts:366-375、356-364）
    sourceAssetRevision,
    knowledgeSnapshotFingerprint,   // 取自 getStudioCanonicalAssetKnowledgeSnapshot（material-studio.ts:3638-3707）
    definitionSnapshot: { name, category, aliases, identityFeatures, positiveLocks, negativeLocks, defaultPrompt, description },
  }],
  objects: [{ sha256, sizeBytes, mimeType, kind }],
  fingerprint: string,   // sha256(stableValue(以上除自身))，算法同 digest()（immutable-mcp-runtime-candidate.ts:77-92）
}
```

校验函数比照 `assertReceipt`（immutable-mcp-runtime-candidate.ts:196-231）：先格式校验，再重算 fingerprint 与自带字段比对，任何不一致直接 throw。导出对源项目是**只读事务**（同 `getStudioCanonicalAssetKnowledgeSnapshot` 的 BEGIN/COMMIT 快照读，material-studio.ts:3648-3649），只在 packageRoot 落盘，不写源项目账本。

## 2. execute_command 合同草案

**`export_studio_cross_episode_asset_package`**
payload：`{ items: [{assetId, expectedRevision}], outputPackageRoot }`。每项带 `expectedRevision` 做导出瞬间 CAS 核对，防并发漂移（校验风格同 studio-video-package.ts:2223-2261 的 `expectedManagedSource` drift 检查）。走 `IdempotentCommandInput` 信封（requestId/idempotencyKey，command-bus.ts:566-579），`commandRequestHash` 防同键异载荷（command-bus.ts:772 起）。

**`import_studio_cross_episode_asset_package`**（单条目粒度；批量=同 packageRoot 下逐条调用。理由：与 `append_studio_asset_version`/`create_studio_asset` 等既有命令一致，一条命令只 CAS 一个聚合根，不引入多资产联合事务的新复杂度）
payload：`{ packageRoot, expectedPackageFingerprint, expectedSourceProjectId, sourceAssetId, sourceVersionId, targetAssetId?, targetExpectedRevision, targetCategory?, targetName?, ... }`（后几项仅新建资产时必填）。
- `expectedPackageFingerprint` 必须等于读到的 `manifest.fingerprint`，`expectedSourceProjectId` 必须等于 `manifest.sourceProjectId`；任一不等即 input-drift fail-closed。
- `targetExpectedRevision`：字面量 `0` = 新建资产 CAS（同 material-studio.ts:389、2565-2566），数字 = 既有资产当前 revision，不符即 `MaterialStudioConflictError`（material-studio.ts:448-458）。
- 涉及"CAS 落盘媒体字节 + 建/追加版本行"两步物理动作（同 `importStudioMedia` 内部两阶段，material-studio.ts:1869-1910），建议纳入 `DURABLE_RECONCILIATION_COMMAND_NAMES`（同 `stage_dudu_readonly_managed_project` 等，command-bus.ts:592-625），防进程中断后重复摄取媒体字节。

## 3. Material Authority 状态机路径

导入落地 = `dudu-readonly-import.ts:1140-1192` 的**前半段**（`ensureImportedMediaOrigin` + `createStudioCanonicalAsset(expectedRevision:0)`（仅新建资产时）+ `appendStudioAssetVersion(reviewStatus:"pending")`），到此为止。

**不复用**同文件 1193-1214 行的自动 approve + 自动 primary 尾段——这是与既有《嘟嘟》只读导入最关键的行为分歧：那里是"历史锁定正典"一次性种子导入（对应 `studio-video-package.ts:290-291` 的 `historical-import` 语义），本合同要求每次导入都必须落 pending、等待目标项目**真实**评审。

后续两步**直接复用、零新增入口**：
- Review 用 `reviewStudioAssetVersion`（material-studio.ts:2769-2818），decision 必须来自目标项目真实评审动作；"源项目 S1 已过审"只写进 `note` 供人读参考，绝不作为 decision 默认值或自动填充。
- Primary 用 `setStudioPrimaryAuthority`（material-studio.ts:2830-2905），其内建"必须存在 pending→approved 不可变审核记录"校验（2876-2887 行）天然拒绝跳审提权，无需新代码即可堵死红线。

## 4. 防伪与完整性

- 逐字节 SHA：导入按 CAS 规则重算 sha256（同 immutable-mcp-runtime-candidate.ts:94-103），并复用 `importStudioMedia` 既有的 `expectedSha256` 落盘校验（material-studio.ts:1840-1858 mismatch 分支）。
- 来源指纹核验：见第2节 `expectedPackageFingerprint`/`expectedSourceProjectId` 双校验，任一失败立即 throw，不做"部分信任导入"。
- 每条 item 携带 `sourceReviewId`/`sourceAuthorityEventId`（真实行 ID）而非裸布尔 `approved:true`，供人工按 ID 回源项目账本核验，形成可核查纸面链条（程序化跨库查询仍被禁止）。
- 篡改 fail-closed：manifest 校验与 receipt 一致——字段格式 + 重算 fingerprint 双通过才可用，任何一处失配整包拒绝，不允许逐条目降级容错。

## 5. 边界清单（明确不做）

- 不做活体同步：导出即快照，源项目后续变更/撤销 Primary 不回传目标项目；要更新须重新导出并重新导入为新的 pending 候选。
- 不做双向绑定：不建跨项目外键；导入产物是目标项目 SQLite 里独立一行，是否与源 assetId 同名由调用方决定，物理上互不关联。
- 不做自动升权：`import_studio_cross_episode_asset_package` 自身绝不调用 review/setPrimary；升权只能是目标项目事后独立发起的命令。
- 不新建第二状态机：pending/approved/rejected/primary 仍是唯一权威表，不加平行审核流程或影子字段。
- 不跨项目直读 SQLite：导出包（manifest.json + objects/sha256）是唯一合法跨项目数据搬运通道；任何运行时代码不得打开另一 projectId 的 `material-studio.sqlite`。
